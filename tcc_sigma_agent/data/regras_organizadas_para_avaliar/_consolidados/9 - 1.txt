# Arquivo: A.yml
title: Suspicious SQL Injection Error Messages In Application Logs
id: 8a670c6d-7189-4b1c-8017-a417ca84a086
status: test
description: >
  Detects database error messages commonly generated during SQL injection
  probing and exploitation attempts. Attackers frequently trigger syntax,
  UNION, quotation, or database parsing errors to identify vulnerable
  parameters, fingerprint the backend DBMS, and refine injection payloads.
references:
  - http://www.sqlinjection.net/errors
  - http://www.sqlinjection.net/detection
author: OpenAI
date: 2026-05-29
tags:
  - attack.initial_access
  - attack.t1190
  - attack.reconnaissance
logsource:
  category: application
  definition: >
    Application, web server, WAF, API gateway, or database error logs
    containing backend SQL exception messages.
detection:
  keywords:
    # MySQL / MariaDB
    - 'You have an error in your SQL syntax'
    - 'check the manual that corresponds to your MySQL server version'
    # Microsoft SQL Server
    - 'Unclosed quotation mark after the character string'
    - 'Incorrect syntax near'
    - 'Msg 105, Level'
    # Oracle
    - 'ORA-01756'
    - 'quoted string not properly terminated'
    - 'ORA-00933'
    - 'SQL command not properly ended'
    # PostgreSQL
    - 'ERROR: syntax error at or near'
    - 'unterminated quoted string'
    # SQLite
    - 'near "*": syntax error'
    - 'SELECTs to the left and right of UNION do not have the same number of result columns'
  condition: keywords
fields:
  - message
  - url
  - uri
  - src_ip
  - user_agent
  - username
falsepositives:
  - Application coding errors causing malformed SQL queries
  - Database migration or deployment failures
  - Software testing activities
level: high

# Arquivo: B.yml
title: Web Application - Database Error Message Disclosure via SQL Injection Probe
id: 5d2a8f1e-3c74-4b19-a061-8e9d45b23761
status: test
description: |
    Detects database-specific error messages appearing in web application or
    proxy response logs, indicating an active error-based SQL injection probe.

    Attackers deliberately inject malformed SQL syntax (unmatched quotes, invalid
    UNION column counts, mismatched types) to trigger DBMS error messages.
    These messages reveal the database engine, query structure, table names and
    column types, enabling crafting of precise follow-on payloads.

    Some advanced SQLi techniques (error-based data extraction) intentionally
    trigger errors to leak data within the error message itself.

    Four DBMS signatures covered: MySQL (error 1064), Microsoft SQL Server
    (Msg 105 / unclosed quotation mark), Oracle (ORA- prefix), PostgreSQL.

    Requires a log source capturing HTTP response body or application exception
    output: WAF (ModSecurity/F5/AWS WAF), reverse proxy with response logging,
    or application server / framework error log (PHP, Django, Rails, Spring).
references:
    - http://www.sqlinjection.net/errors
    - https://attack.mitre.org/techniques/T1190/
    - https://attack.mitre.org/techniques/T1082/
author: Security Team
date: 2026-05-25
tags:
    - attack.initial_access
    - attack.t1190   # Exploit Public-Facing Application
    - attack.discovery
    - attack.t1082   # System Information Discovery (DBMS fingerprinting via errors)
logsource:
    category: webserver
detection:
    selection_mysql:
        # MySQL syntax error — format: "1064 - You have an error in your SQL syntax..."
        message|contains:
            - 'You have an error in your SQL syntax'
            - 'check the manual that corresponds to your MySQL server version'
            - 'mysql_fetch_array()'         # PHP MySQL API error exposure
            - 'mysql_num_rows() expects parameter'
    selection_mssql:
        # SQL Server errors — format: "Msg 105, Level 15, State 1, Line 1"
        message|contains:
            - 'Unclosed quotation mark after the character string'
            - 'Incorrect syntax near'
            - 'Msg 105, Level 15'
            - 'Microsoft OLE DB Provider for SQL Server'
            - 'ODBC SQL Server Driver'
    selection_oracle:
        # Oracle errors — ALL start with "ORA-" followed by 5-digit code
        message|contains:
            - 'ORA-01756'  # quoted string not properly terminated
            - 'ORA-00907'  # missing right parenthesis
            - 'ORA-00933'  # SQL command not properly ended
            - 'ORA-00942'  # table or view does not exist
            - 'quoted string not properly terminated'
    selection_pgsql:
        # PostgreSQL errors — common in modern stacks (Django, Rails, Node)
        message|contains:
            - 'PSQLException'
            - 'ERROR: unterminated quoted string'
            - 'ERROR: syntax error at or near'
            - 'pg_query(): Query failed'
    filter_dev_environments:
        # Suppress known non-production hostnames to reduce noise from dev/QA
        # cs-host|contains:
        #     - 'dev.'
        #     - 'staging.'
        #     - 'test.'
        #     - 'localhost'
        sc-status: null   # placeholder — tune with known dev hostnames
    condition: (1 of selection_*) and not filter_dev_environments
fields:
    - c-ip
    - cs-uri-stem
    - cs-uri-query
    - sc-status
    - message
    - cs(User-Agent)
falsepositives:
    - Development/QA environments with error reporting enabled — use filter_dev_environments
    - Misconfigured production apps permanently leaking DB errors to all users
    - Automated vulnerability scanners (Burp Suite, sqlmap) during authorized testing
    - Legacy PHP applications using deprecated mysql_*() functions for internal ops
level: high

# Arquivo: C.yml
title: SQL Injection Database Error Messages Exposure
id: dbcc81d9-5f25-4b07-95de-bc83602f354e
status: experimental
description: Detects standard database backend syntax, driver, and type conversion error messages appearing within web application or application server logs. These verbose errors are highly characteristic of active error-based SQL injection (SQLi) probing, where adversaries intentionally pass malformed inputs to infer table structures and leak backend context.
references:
    - http://www.sqlinjection.net/errors
author: Security Operations Center
date: 2026/05/29
tags:
    - attack.initial_access
    - attack.t1190 # Exploit Public-Facing Application
logsource:
    category: application
detection:
    selection:
        Message|contains:
            # Microsoft SQL Server
            - 'Unclosed quotation mark after the character string'
            - 'Conversion failed when converting the varchar value'
            - 'Microsoft OLE DB Provider for SQL Server'
            - 'Syntax error in string in query expression'
            # MySQL
            - 'you have an error in your sql syntax'
            - 'Illegal mix of collations'
            - 'supplied argument is not a valid MySQL result'
            # Oracle
            - 'ORA-00933: SQL command not properly ended'
            - 'ORA-01756: quoted string not properly terminated'
            - 'ORA-00921: unexpected end of SQL command'
            # PostgreSQL
            - 'ERROR: syntax error at or near'
            - 'unterminated quoted string at or near'
            - 'invalid input syntax for type integer'
    condition: selection
falsepositives:
    - Broken production code or poorly written dynamic SQL components executing authentic user input bugs.
    - Authorized database schema upgrades or debugging activities performed by software development or QA teams.
level: high
