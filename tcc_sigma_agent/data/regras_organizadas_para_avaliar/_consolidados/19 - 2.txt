# Arquivo: D.yml
title: Kubernetes Remote Command Execution via kubectl exec Into Container
id: 8d2f4a1b-6c3e-4b7f-a5d2-9e1c8b3f6a42
status: experimental
description: >
  Detects invocation of the exec subresource on a Kubernetes pod object as
  recorded in the API server audit log. The kubectl exec command — and any
  equivalent API call — triggers a create verb against the pods/exec
  subresource, causing the API server to open an interactive stream directly
  into a running container. An adversary with sufficient RBAC permissions or
  a stolen service account token can abuse this capability to spawn an
  arbitrary shell inside a compromised pod, enumerate the container filesystem,
  exfiltrate secrets mounted at runtime, pivot to other pods on the same
  network, or execute further attack stages entirely within the container
  runtime, bypassing host-level EDR and traditional endpoint controls. This
  technique is listed in the Microsoft Threat Matrix for Kubernetes under
  the Execution tactic. Detection matches the combination of create verb,
  pods resource, and exec subresource as they appear in structured Kubernetes
  audit log events, which together uniquely identify an exec session initiation
  regardless of the client used (kubectl, client-go, or direct API calls).
references:
  - https://microsoft.github.io/Threat-Matrix-for-Kubernetes/techniques/Exec%20into%20container/
author: Senior Threat Detection Engineer
date: 2026-05-25
tags:
  - attack.execution
  - attack.lateral_movement
  - attack.t1609
logsource:
  product: kubernetes
  category: application
  service: audit
detection:
  selection:
    verb: create
    objectRef.resource: pods
    objectRef.subresource: exec
  condition: selection
falsepositives:
  - Legitimate platform engineering or SRE workflows where operators
    exec into pods for authorised debugging, log collection, or break-glass
    incident response procedures in production environments.
  - Automated testing frameworks or CI/CD pipelines that exec into
    ephemeral containers as part of integration test setup, health checks,
    or deployment verification steps.
  - Kubernetes operators or controllers that programmatically exec into
    pods to perform lifecycle management tasks such as database migration
    or configuration bootstrapping.
level: medium
