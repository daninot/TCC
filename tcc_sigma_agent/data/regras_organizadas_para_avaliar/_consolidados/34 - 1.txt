# Arquivo: A.yml
title: Sha1-Hulud npm Supply Chain - Malicious File Drop During Package Install
id: 7f3e9a2c-4d81-4b07-ae56-1c8f6d903b4e
status: experimental
description: |
    Detects files characteristic of the Sha1-Hulud 2.0 npm supply chain campaign
    being written to disk. The malware executes during the npm preinstall lifecycle
    hook and drops a fixed set of payload and exfiltration staging files:
    setup_bun.js, bun_environment.js, cloud.json, contents.json, environment.json,
    truffleSecrets.json, and a backdoor GitHub Actions workflow (discussion.yaml).
    These filenames are hardcoded in the payload and have not been observed in
    legitimate npm packages. The rule triggers on any process creating one of these
    files where the parent process chain includes a Node.js or npm-related binary,
    consistent with install-time lifecycle script execution.

    References:
      - https://www.wiz.io/blog/shai-hulud-2-0-ongoing-supply-chain-attack
      - https://www.aikido.dev/blog/shai-hulud-strikes-again-hitting-zapier-ensdomains
      - https://semgrep.dev/blog/2025/digging-for-secrets-sha1-hulud-the-second-coming-of-the-npm-worm/

author: Claude (based on Wiz Research / Aikido / Semgrep public reporting)
date: 2026-06-06
modified: 2026-06-06
tags:
    - attack.execution
    - attack.t1059.006        # Command and Scripting Interpreter: JavaScript
    - attack.exfiltration
    - attack.t1020            # Automated Exfiltration
    - attack.persistence
    - attack.t1053.005        # Scheduled Task/Job (GitHub Actions used as persistence)
    - attack.credential_access
    - attack.t1552.001        # Unsecured Credentials: Credentials In Files
    - tlp:white

logsource:
    category: file_event
    # Tested against Sysmon (EventID 11), Elastic Endpoint, Falcon, and
    # auditd with FILE_CREATE/FILE_MODIFY syscall rules. Adjust field names
    # to match your EDR's schema if necessary.

detection:
    selection_filenames:
        # Hardcoded payload and staging filenames written by the malware.
        # All five data files can appear in any working directory; discussion.yaml
        # will appear under .github/workflows/ relative to the repo root.
        TargetFilename|endswith:
            - '\setup_bun.js'
            - '/setup_bun.js'
            - '\bun_environment.js'
            - '/bun_environment.js'
            - '\cloud.json'
            - '/cloud.json'
            - '\contents.json'
            - '/contents.json'
            - '\truffleSecrets.json'
            - '/truffleSecrets.json'
            - '\.github\workflows\discussion.yaml'
            - '/.github/workflows/discussion.yaml'

    selection_process:
        # The file must be written by a process consistent with npm lifecycle
        # script execution. Legitimate preinstall/postinstall hooks run under
        # node, npm, npx, or their wrappers. Adjust paths as needed for your OS.
        Image|endswith:
            - '\node.exe'
            - '/node'
            - '\npm.cmd'
            - '/npm'
            - '\npx.cmd'
            - '/npx'

    # environment.json is a common enough filename to generate noise on its own.
    # Require the parent-process filter when matching it in isolation.
    selection_environment_json_only:
        TargetFilename|endswith:
            - '\environment.json'
            - '/environment.json'

    condition: >
        ( selection_filenames and selection_process )
        or ( selection_environment_json_only and selection_process )

falsepositives:
    - Legitimate tooling that also uses the filename cloud.json or contents.json
      in a node_modules context is theoretically possible but has not been
      observed at meaningful scale. Scope the rule to build/CI hosts and
      developer workstations rather than production servers to reduce noise.
    - The discussion.yaml path match is very specific to this campaign and is
      unlikely to produce false positives.

level: high

fields:
    - TargetFilename
    - Image
    - ParentImage
    - User
    - ProcessId
    - ParentProcessId
    - CommandLine

# Arquivo: C.yml
title: Shai-Hulud Supply Chain Indicators — Malicious NPM/Git Activity
id: 2c9b7f4e-2026-shai-hulud-0001
status: experimental
description: Detects indicators consistent with the Shai‑Hulud supply‑chain campaign: malicious or unexpected NPM package activity, postinstall/prepare scripts that fetch and execute remote code, .npmrc registry redirection, git commits introducing obfuscated payloads or long hex/sha1 blobs, and installs pulling packages from suspicious GitHub URLs. These patterns help identify typosquatting, repo compromise, or injected build/install-time execution used to propagate a worm-like supply chain infection.
author: Detection Engineer
date: 2026-06-06
references:
  - https://www.wiz.io/blog/shai-hulud-2-0-ongoing-supply-chain-attack
  - https://www.aikido.dev/blog/shai-hulud-strikes-again-hitting-zapier-ensdomains
  - https://semgrep.dev/blog/2025/digging-for-secrets-sha1-hulud-the-second-coming-of-the-npm-worm/
logsource:
  product: code_repository
  service: git/npm/ci
  category: code_change
detection:
  selection_package_json_postinstall:
    FilePath|endswith:
      - "package.json"
    FileContent|re:
      - '(?i)"(postinstall|prepare|install|preinstall)"\s*:\s*".{0,200}(curl|wget|powershell|Invoke-WebRequest|node\s+-e|npm\s+run|bash|sh)\b'
  selection_npm_process_fetch_github:
    EventType: process_creation
    Image|re:
      - '(?i)\\(npm|node|npx)(\.exe)?$'
    CommandLine|re:
      - '(?i)\binstall\b.*(github\.com|raw\.githubusercontent\.com|gitlab\.com|bitbucket\.org)'
      - '(?i)(npm\s+install\s+[^ ]+@git\+https?:\/\/|npm\s+install\s+https?:\/\/github\.com)'
  selection_npmrc_registry_redirect:
    FilePath|re:
      - '(?i)(^|/)\.npmrc$'
    FileContent|re:
      - '(?i)registry\s*=\s*(http:\/\/|https?:\/\/)(?!registry\.npmjs\.org)'
  selection_git_commit_obfuscated_blob:
    EventType: git_commit
    CommitMessage|re:
      - '(?i)(postinstall|prepare|added\s+package|typo|fix\spackage|supply[-_ ]chain)'
    FileDiff|re:
      - '(?i)([A-Fa-f0-9]{40,}|base64,[A-Za-z0-9+/=]{200,})'
  selection_sha1_like_secret_in_repo:
    FileContent|re:
      - '(?i)(secret|token|key|private_key|api_key|password).{0,60}([a-f0-9]{40})'
  selection_suspicious_dependency_name:
    FilePath|endswith:
      - "package.json"
    FileContent|re:
      - '(?i)"dependencies"\s*:\s*{[^}]*"(?:[a-z0-9\-_]*hulud|shai[-_ ]hulud|shaihulud|shai[-_ ]h[a0o]lud|shai[-_ ]h[a0o]lud[a-z0-9\-_]*)"\s*:'
  condition: selection_package_json_postinstall or selection_npm_process_fetch_github or selection_npmrc_registry_redirect or selection_git_commit_obfuscated_blob or selection_sha1_like_secret_in_repo or selection_suspicious_dependency_name
fields:
  - timestamp
  - Repository
  - CommitHash
  - CommitAuthor
  - CommitMessage
  - FilePath
  - FileContentSnippet
  - Image
  - CommandLine
  - User
falsepositives:
  - Legitimate packages that use postinstall scripts for build steps or native module compilation (node-gyp) — verify publisher and script contents.
  - Internal registries or mirrors configured via .npmrc by DevOps teams.
  - Large binary blobs or encoded assets intentionally committed by developers (media, build artifacts) — validate with development teams.
level: high
tags:
  - attack.supply_chain
  - attack.persistence
  - malware.npm
  - detection.code_repo
  - threat.shai-hulud
notes: |
  - Tuning: whitelist known build scripts, internal registries, and trusted package names; restrict detection to changes from non‑trusted authors or to production branches.
  - Investigation: retrieve full commit diffs and package.json contents, verify package publisher and signatures, inspect postinstall/prepare scripts for remote fetch-and-execute patterns, check .npmrc for registry redirection, and search the environment for installed packages with matching names or hashes.
  - Response: if malicious activity is confirmed, remove compromised packages, rotate affected credentials, revoke tokens exposed in repos, block malicious registries/URLs, and perform a tenant-wide hunt for other infected repositories or CI artifacts.
