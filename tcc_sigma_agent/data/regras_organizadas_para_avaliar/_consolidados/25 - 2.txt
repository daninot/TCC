# Arquivo: B.yml
title: Obfuscated PowerShell via STDIN Launcher (Invoke-Obfuscation STDIN+)
id: 3b9f6a2d-7c4e-4f1a-8d2b-5e6f7a9c0b1d
status: experimental
description: Detects attempts to launch PowerShell by piping input through cmd.exe (stdin-based launcher) commonly used by Invoke-Obfuscation and similar toolchains to evade script-argument detections. Matches cmd.exe invocations using /c or /r that pipe into a PowerShell or pwsh process and include stdin-style invocation (e.g., -Command -) or flags like -NoExit.
author: Senior Threat Detection Engineer
date: 2026/06/06
references:
  - [https://github.com/SigmaHQ/sigma/issues/1009](https://github.com/SigmaHQ/sigma/issues/1009)
tags:
  - attack.execution
  - attack.t1059.001
  - obfuscation
  - powershell
logsource:
  product: windows
  category: ps_module
  description: PowerShell and process creation telemetry that includes the full command line or payload field. Ensure module/process logging is enabled and forwarded to the SIEM.
detection:
  selection:
    Payload|re: '(?i)cmd(?:\.exe)?\s+\/[cr]\b.*\|\s*(?:powershell|pwsh)(?:\.exe)?\b.*(?:-Command\s+[-]|-\s*$|-NoExit\b)'
  condition: selection
falsepositives:
  - Legitimate administrative or automation scripts that intentionally pipe content into PowerShell (debugging, CI/CD, installers).
  - Security tooling or endpoint management that uses stdin piping for scripted deployments.
level: high

# Arquivo: E.yml
title: Invoke-Obfuscation STDIN+ Launcher via cmd.exe Pipe to PowerShell
id: 3d7f2c1a-8b4e-4f9d-a6b3-5e2c1d8f4a72
status: experimental
description: >
  Detects the Invoke-Obfuscation STDIN+ launcher technique, in which cmd.exe
  is used with the /c or /r flag to pipe obfuscated PowerShell content into
  the PowerShell engine via standard input rather than as a command-line
  argument. This method evades script-block and command-line based detections
  because the malicious payload is delivered over stdin and never appears in
  the PowerShell process command line. The characteristic pattern combines a
  cmd.exe invocation with a /c or /r execution flag, a PowerShell invocation,
  and indicators of stdin consumption (-noexit flag or the $input automatic
  variable, both of which signal that PowerShell is reading from the pipe).
  Detection is performed via a single regular expression on the PowerShell
  Module Logging Payload field, which captures the content passed through
  the pipeline regardless of argument obfuscation. Requires PowerShell Module
  Logging to be enabled via Group Policy or the registry key
  HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ModuleLogging.
references:
  - https://github.com/SigmaHQ/sigma/issues/1009
author: Senior Threat Detection Engineer
date: 2026-05-25
tags:
  - attack.defense_evasion
  - attack.execution
  - attack.t1027
  - attack.t1059.001
logsource:
  category: ps_module
  product: windows
detection:
  selection:
    Payload|re: '(?i)cmd\b.{0,50}(/c|/r).{0,200}powershell.{0,200}(-noexit|\$input)'
  condition: selection
falsepositives:
  - Legitimate administrative scripts or build automation pipelines that
    invoke PowerShell by piping content through cmd.exe as an approved
    cross-shell execution pattern. Any match should be reviewed against
    the invoking user context and the piped payload content before dismissal.
level: high
