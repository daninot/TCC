# Arquivo: C.yml
title: Azure Entra ID Sign-In via OAuth 2.0 Device Code Flow
id: b3c1f7e2-4a8d-4b9c-a6e3-2f5d1c8b3e70
status: experimental
description: >
  Detects a successful authentication to Microsoft Entra ID (Azure AD) that used
  the OAuth 2.0 Device Code authorization grant. This flow is designed exclusively
  for input-constrained devices (e.g., smart TVs, IoT endpoints, CLI tooling).
  When observed outside that context it may indicate a device-code phishing attack
  in which an adversary tricks a victim into entering an attacker-controlled device
  code, yielding a fully authenticated token to the attacker without requiring
  credential capture. It can also indicate a misconfigured application or a
  deliberate policy bypass.
references:
  - https://learn.microsoft.com/en-us/entra/architecture/security-operations-applications#application-authentication-flows
author: Senior Threat Detection Engineer
date: 2026-05-25
tags:
  - attack.credential_access
  - attack.initial_access
  - attack.t1528
  - attack.t1566
logsource:
  product: azure
  service: signinlogs
detection:
  selection:
    AuthenticationProtocol: deviceCode
    ResultType: '0'
  condition: selection
falsepositives:
  - Legitimate input-constrained devices such as smart TVs, set-top boxes, kiosks,
    or IoT endpoints that are enrolled and managed by the organization and
    intentionally rely on the device code flow to complete user authentication.
  - Approved CLI tools and developer workflows (e.g., Azure CLI, VS Code device
    login) where the device code flow is explicitly authorized by policy.
  - Sanctioned automated testing pipelines that authenticate via device code in
    a controlled lab environment.
level: medium

# Arquivo: E.yml
title: OAuth 2.0 Device Code Flow Authentication
id: 5c6d7e8f-9a0b-1c2d-3e4f-5a6b7c8d9e0f
status: experimental
description: Detects authentication using the OAuth 2.0 Device Code flow in Azure AD sign-in logs. This flow is intended for input-constrained devices; when observed outside that scenario, it may indicate a device-code phishing attack, misconfigured application, or attacker abusing the flow to obtain tokens from a victim's session.
references:
  - https://learn.microsoft.com/en-us/entra/architecture/security-operations-applications#application-authentication-flows
author: Senior Threat Detection Engineer
date: 2026-05-25
tags:
  - attack.credential-access
  - attack.t1528
  - attack.t1550
logsource:
  product: azure
  service: signinlogs
detection:
  selection:
    AuthenticationProtocol: oauth2
  filter_device_code:
    AuthenticationProcessingDetails|contains: Device Code
  condition: selection and filter_device_code
falsepositives:
  - Legitimate usage by input-constrained devices such as smart TVs, IoT devices, CLI tools, or headless systems that require the device code flow for authentication.
level: medium
