# Arquivo: B.yml
title: Windows - Suspicious LSASS Process Memory Access (Credential Dumping - T1003.001)
id: fc4f4817-3c85-4b92-a013-6d8e3c9f5b27
status: test
description: |
    Detects suspicious access to the LSASS (Local Security Authority Subsystem
    Service) process that may indicate credential dumping, synthesised from five
    sources covering the detection surface:

    1. Microsoft Process Security and Access Rights documentation — defines the
       bit flags composing the GrantedAccess masks (PROCESS_VM_READ 0x10,
       PROCESS_QUERY_INFORMATION 0x400, PROCESS_QUERY_LIMITED_INFORMATION 0x1000,
       PROCESS_DUP_HANDLE 0x40).

    2. Cyberwardog (Roberto Rodriguez) LSASS hunting blog — established that
       Sysmon EventID 10 GrantedAccess masks containing PROCESS_VM_READ against
       lsass.exe are the primary host-based indicator of credential dumping.

    3. Hunting for Credentials Dumping (Teymur Kheirkhabarov) — catalogued the
       specific GrantedAccess masks used by Mimikatz, procdump, WCE, gsecdump,
       and other credential-theft tools against lsass.exe.

    4. Tom Ueltschi FIRST 2017 Sysmon presentation — demonstrated how
       Sysmon ProcessAccess (EventID 10) captures the SourceImage/TargetImage/
       GrantedAccess tuple that makes this detection possible without kernel hooks.

    5. OneDrive presentation — threat hunting context establishing that the
       combination of GrantedAccess flags and non-system SourceImage is the
       high-fidelity pivot for this class of attacks.

    Detection logic: TargetImage = lsass.exe AND GrantedAccess in a set of
    values observed in credential dumping tools AND SourceImage not matching
    known-legitimate system/security processes.

    Key access masks from the research:
      0x1010 — PROCESS_QUERY_LIMITED_INFORMATION | PROCESS_VM_READ (Mimikatz default)
      0x1410 — adds PROCESS_QUERY_INFORMATION to 0x1010 (Mimikatz sekurlsa)
      0x1418 — adds PROCESS_SUSPEND_RESUME
      0x1438 — adds further flags (Cobalt Strike variants)
      0x0040 — PROCESS_DUP_HANDLE alone (handle duplication bypass technique)
      0x1F1FFF / 0x1FFFFF — PROCESS_ALL_ACCESS (crude tools, old Metasploit)
references:
    - https://learn.microsoft.com/en-us/windows/win32/procthread/process-security-and-access-rights
    - https://web.archive.org/web/20230208123920/https://cyberwardog.blogspot.com/2017/03/chronicles-of-threat-hunter-hunting-for_22.html
    - https://www.slideshare.net/heirhabarov/hunting-for-credentials-dumping-in-windows-environment
    - https://web.archive.org/web/20230420013146/http://security-research.dyndns.org/pub/slides/FIRST2017/FIRST-2017_Tom-Ueltschi_Sysmon_FINAL_notes.pdf
    - https://attack.mitre.org/techniques/T1003/001/
author: Security Team
date: 2026-06-07
tags:
    - attack.credential_access
    - attack.t1003.001   # OS Credential Dumping: LSASS Memory
logsource:
    category: process_access
    product: windows
detection:
    selection_lsass_target:
        TargetImage|endswith: '\lsass.exe'
    selection_vm_read_masks:
        # Access masks observed in credential dumping tools — all include
        # PROCESS_VM_READ (0x10) or PROCESS_DUP_HANDLE (0x40) against lsass.exe.
        # Source: Cyberwardog blog, Kheirkhabarov Hunting presentation, Tom Ueltschi FIRST2017
        GrantedAccess|in:
            - '0x1010'    # PROCESS_QUERY_LIMITED_INFORMATION | PROCESS_VM_READ (Mimikatz default)
            - '0x1410'    # + PROCESS_QUERY_INFORMATION (Mimikatz sekurlsa::logonpasswords)
            - '0x1418'    # + PROCESS_SUSPEND_RESUME (procdump/WCE variants)
            - '0x1438'    # + additional flags (Cobalt Strike, Empire Invoke-Mimikatz)
            - '0x143a'    # Cobalt Strike loader variant
            - '0x1000'    # PROCESS_QUERY_LIMITED_INFORMATION (recon-only, lower confidence)
            - '0x0040'    # PROCESS_DUP_HANDLE alone (handle duplication bypass)
            - '0x0410'    # PROCESS_QUERY_INFORMATION | PROCESS_VM_READ
            - '0x1f1fff'  # PROCESS_ALL_ACCESS (old Metasploit, gsecdump)
            - '0x1fffff'  # PROCESS_ALL_ACCESS (modern tools, crude loaders)
    filter_system_processes:
        # Windows system processes that legitimately access lsass.exe internals
        SourceImage|in:
            - 'C:\Windows\System32\csrss.exe'
            - 'C:\Windows\System32\wininit.exe'
            - 'C:\Windows\System32\services.exe'
            - 'C:\Windows\System32\lsass.exe'      # self-access during normal operation
            - 'C:\Windows\System32\svchost.exe'
            - 'C:\Windows\System32\taskmgr.exe'
            - 'C:\Windows\System32\WerFault.exe'    # Windows Error Reporting
    filter_security_software:
        # AV / EDR products that legitimately read LSASS for memory scanning
        # Populate with your environment's specific security product paths:
        SourceImage|contains:
            - '\MsMpEng.exe'          # Windows Defender
            - '\MsSense.exe'          # Microsoft Defender for Endpoint
            - '\SecurityHealthService.exe'
            - '\CylanceSvc.exe'       # Cylance
            - '\bdservicehost.exe'    # Bitdefender
            - '\SentinelAgent.exe'    # SentinelOne
            - '\CrowdStrike\'
    condition: >
        selection_lsass_target
        and selection_vm_read_masks
        and not filter_system_processes
        and not filter_security_software
fields:
    - SourceImage
    - SourceCommandLine
    - TargetImage
    - GrantedAccess
    - CallTrace
    - User
    - ProcessId
falsepositives:
    - Security scanning products not listed in filter_security_software
    - Debugging tools (WinDbg, x64dbg) in development environments
    - Custom enterprise monitoring agents that enumerate lsass for health checks
    - Windows Credential Guard transitions (limited access masks only)
level: high

# Arquivo: C.yml
title: Suspicious Process Access To LSASS (Potential Credential Dumping)
id: 4a2d8e1f-7b3c-4a9d-bd9e-2a1748291a55
status: experimental
description: |
  Detects suspicious process access requests to the LSASS process (lsass.exe) by monitoring Sysmon Event ID 10.
  Adversaries frequently open handles to LSASS with specific access rights like PROCESS_VM_READ and PROCESS_QUERY_INFORMATION 
  to dump memory contents and extract plain-text credentials or NTLM hashes, as outlined in classic credential dumping research.
author: Gemini
date: 2026/06/08
references:
    - https://learn.microsoft.com/en-us/windows/win32/procthread/process-security-and-access-rights
    - https://web.archive.org/web/20230208123920/https://cyberwardog.blogspot.com/2017/03/chronicles-of-threat-hunter-hunting-for_22.html
    - https://www.slideshare.net/heirhabarov/hunting-for-credentials-dumping-in-windows-environment
tags:
    - attack.credential_access
    - attack.t1003.001
logsource:
    category: process_access
    product: windows
detection:
    selection:
        TargetImage|endswith: '\lsass.exe'
        GrantedAccess|contains:
            - '0x1410'   # PROCESS_VM_READ | PROCESS_QUERY_INFORMATION
            - '0x1010'   # PROCESS_VM_READ | PROCESS_QUERY_LIMITED_INFORMATION
            - '0x1F0FFF' # PROCESS_ALL_ACCESS
            - '0x1438'   # Specific Mimikatz / ProcDump combination
            - '0x1418'   # Specific Task Manager dump combination
    filter_legitimate_sources:
        SourceImage|endswith:
            - '\svchost.exe'
            - '\lsass.exe'
            - '\services.exe'
            - '\wininit.exe'
            - '\csrss.exe'
            - '\msiexec.exe'
    condition: selection and not filter_legitimate_sources
falsepositives:
    - Antivirus, Endpoint Detection and Response (EDR) agents, or local security software actively scanning memory.
    - Specialized identity management or IT administration tools running with high privileges.
level: high

# Arquivo: D.yml
title: Suspicious LSASS Access and Credential Dumping Indicators
id: 2026-06-08-windows-lsass-access-dump
status: experimental
description: Detects attempts to read or dump LSASS memory and related credential dumping activity by monitoring high-privilege process access to lsass.exe, creation or execution of known dumping tools and debugger patterns, SeDebugPrivilege assignments/usage, and creation of dump files in user-writable locations. Correlate process access with dump file writes or suspicious child processes to increase confidence.
author: Detection Engineer
date: 2026-06-08
references:
  - https://learn.microsoft.com/en-us/windows/win32/procthread/process-security-and-access-rights
  - https://web.archive.org/web/20230208123920/https://cyberwardog.blogspot.com/2017/03/chronicles-of-threat-hunter-hunting-for_22.html
  - https://www.slideshare.net/heirhabarov/hunting-for-credentials-dumping-in-windows-environment
  - https://web.archive.org/web/20230420013146/http://security-research.dyndns.org/pub/slides/FIRST2017/FIRST-2017_Tom-Ueltschi_Sysmon_FINAL_notes.pdf
logsource:
  product: windows
  service: sysmon,security
  category: process_access,process_creation,file_event,security
detection:
  selection_lsass_process_access:
    EventID: 10
    TargetImage|re:
      - '(?i)\\lsass\.exe$'
    GrantedAccess|re:
      - '(?i)(0x0010|0x0020|0x0008|0x0400|0x0002|0x1fffff|0x1f0fff)'
  selection_procdump_usage:
    EventID: 1
    Image|re:
      - '(?i)\\procdump(?:64)?(\.exe)?$'
    CommandLine|re:
      - '(?i)\b(-ma|-accepteula|-s|-mp)\b'
      - '(?i)\blsass\.exe\b'
  selection_rundll_minidump:
    EventID: 1
    Image|re:
      - '(?i)\\rundll32\.exe$'
    CommandLine|re:
      - '(?i)comsvcs\.dll,MiniDump'
  selection_mimikatz_activity:
    EventID: 1
    Image|re:
      - '(?i)\\mimikatz(\.exe|\.dll)?$'
    CommandLine|re:
      - '(?i)sekurlsa|logonpasswords|lsadump'
  selection_debugger_tools:
    EventID: 1
    Image|re:
      - '(?i)\\(cdb|windbg|adplus|taskmgr|procdump)\.exe$'
  selection_dump_file_written:
    EventID: 11
    TargetFilename|re:
      - '(?i)\\.*(lsass|memory|cred|creds|dump).*\.(dmp|dump|bin|log|txt)$'
      - '(?i)\\Users\

\[^\\]

+\\AppData\\Local\\Temp\\.*\.(dmp|dump|bin)$'
  selection_sedebug_priv_assigned:
    EventID: 4672
    Privileges|re:
      - '(?i)SeDebugPrivilege'
  selection_sedebug_priv_used:
    EventID: 4673
    PrivilegeList|re:
      - '(?i)SeDebugPrivilege'
  correlation_access_then_dump:
    - when: selection_lsass_process_access
      then: selection_dump_file_written
      within: "2m"
  correlation_access_then_tool:
    - when: selection_lsass_process_access
      then: selection_procdump_usage
      within: "2m"
  condition: >
    selection_lsass_process_access
    or selection_procdump_usage
    or selection_rundll_minidump
    or selection_mimikatz_activity
    or selection_debugger_tools
    or selection_sedebug_priv_assigned
    or selection_sedebug_priv_used
    or correlation_access_then_dump
    or correlation_access_then_tool
fields:
  - timestamp
  - EventID
  - ComputerName
  - SubjectUserName
  - Image
  - ParentImage
  - CommandLine
  - TargetImage
  - GrantedAccess
  - AccessMask
  - TargetFilename
  - ProcessId
  - ParentProcessId
falsepositives:
  - Legitimate administrative or developer debugging activity (procdump, windbg, taskmgr) performed by IT or support teams.
  - Endpoint protection, monitoring, or backup agents that legitimately read process memory or create dumps.
  - Forensic collections performed by incident response teams.
level: high
tags:
  - attack.credential_access
  - attack.t1003
  - detection.windows.sysmon
  - hunting
notes: |
  - Tuning: whitelist known management and monitoring hosts, signed debugging tools, and scheduled support activity; require correlation (process access + dump file write or known dumping tool execution) to reduce noise.
  - Investigation: collect full process trees, command lines, the created dump file (preserve and hash), digital signatures of involved binaries, account context, and recent privilege assignments; search for lateral movement or C2 activity following the dump.
  - Response: if malicious, isolate the host, remove unauthorized dumps, rotate exposed credentials, revoke compromised accounts, and perform a broader hunt for similar indicators across the environment.

    EventID: 10
