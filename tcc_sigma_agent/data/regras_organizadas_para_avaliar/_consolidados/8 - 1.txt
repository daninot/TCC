# Arquivo: B.yml
title: Internet Explorer Trusted Sites Zone Modification via Registry
id: e4b2c1da-3f51-4fa3-99b3-fd82a4773c8d
status: experimental
description: Detects registry modifications that add a domain to the Internet Explorer "Trusted Sites" security zone (Zone 2). Adversaries can exploit this technique to bypass browser security controls, enabling the execution of malicious scripts, unsigned controls, or automatic file downloads under lowered security restrictions.
references:
    - https://github.com/redcanaryco/atomic-red-team/blob/f339e7da7d05f6057fdfcdd3742bfcf365fee2a9/atomics/T1112/T1112.md#atomic-test-4---add-domain-to-trusted-sites-zone
    - https://learn.microsoft.com/en-us/troubleshoot/developer/browsers/security-privacy/ie-security-zones-registry-entries
author: Security Operations Center
date: 2026/05/26
tags:
    - attack.defense_evasion
    - attack.t1112 # Modify Registry
logsource:
    product: windows
    category: registry_set
detection:
    selection_path:
        TargetObject|contains:
            - '\Software\Microsoft\Windows\CurrentVersion\Internet Settings\ZoneMap\Domains\'
            - '\Software\Microsoft\Windows\CurrentVersion\Internet Settings\ZoneMap\EscDomains\'
    selection_zone:
        # Zone value '2' represents the 'Trusted Sites' zone
        Details|contains:
            - '2'
            - '0x00000002'
    condition: selection_path and selection_zone
falsepositives:
    - Legitimate enterprise Group Policy Objects (GPOs) pushing approved corporate domains to the Trusted Sites list.
    - Automated deployment scripts or administrative software installations configuring vendor or updater domains.
level: medium

# Arquivo: D.yml
title: Windows - Domain Added to IE Trusted Sites Zone via ZoneMap Registry (T1112)
id: 4b8a2e3f-19c6-4d07-a85e-0c3b7f6d9142
status: test
description: |
    Detects registry writes that add a domain, subdomain, or IP range to the
    Internet Explorer / Edge Legacy Trusted Sites Zone (Zone 2) via the
    ZoneMap registry keys, matching Atomic Red Team T1112 Test #4.

    Attackers add attacker-controlled domains to the Trusted Sites Zone to
    disable IE/Edge security prompts for ActiveX controls, scripting, and
    file downloads from those domains, enabling covert C2 channels over
    browsers (e.g., C2 over Office365 as documented in Black Hat USA 2017).

    Key schema (per Microsoft KB 182569):
      ZoneMap\Domains\<domain>\<subdomain>
        Value name  = protocol (http, https, ftp, *)
        DWORD value = security zone number (2 = Trusted Sites)
      ZoneMap\EscDomains\ — same schema, IE Enhanced Security Config (servers)
      ZoneMap\Ranges\     — IP address ranges instead of FQDNs

    Covers both HKCU (per-user) and HKLM (machine-wide) hives, and the
    wildcard protocol '*' which maps ALL protocols to Trusted Sites in one write.
references:
    - https://github.com/redcanaryco/atomic-red-team/blob/f339e7da7d05f6057fdfcdd3742bfcf365fee2a9/atomics/T1112/T1112.md#atomic-test-4---add-domain-to-trusted-sites-zone
    - https://learn.microsoft.com/en-us/troubleshoot/developer/browsers/security-privacy/ie-security-zones-registry-entries
    - https://www.blackhat.com/docs/us-17/wednesday/us-17-Dods-Infecting-The-Enterprise-Abusing-Office365-Powershell-For-Covert-C2.pdf
    - https://attack.mitre.org/techniques/T1112/
author: Security Team
date: 2026-05-25
tags:
    - attack.defense_evasion
    - attack.command_and_control
    - attack.t1112       # Modify Registry
    - attack.t1562.001   # Impair Defenses: Disable or Modify Tools (browser security)
    - attack.t1071.001   # Application Layer Protocol: Web (C2 via HTTP/HTTPS)
logsource:
    category: registry_set
    product: windows
detection:
    selection_domains:
        # ZoneMap\Domains — FQDN-based Trusted Site assignment (HKCU or HKLM)
        TargetObject|contains: '\Internet Settings\ZoneMap\Domains\'
        Details|contains: '0x00000002'  # Zone 2 = Trusted Sites
    selection_esc_domains:
        # ZoneMap\EscDomains — IE Enhanced Security Config variant (server OS)
        TargetObject|contains: '\Internet Settings\ZoneMap\EscDomains\'
        Details|contains: '0x00000002'
    selection_ranges:
        # ZoneMap\Ranges — IP range mapped to Trusted Sites instead of FQDN
        TargetObject|contains: '\Internet Settings\ZoneMap\Ranges\'
        Details|contains: '0x00000002'
    filter_gpo_processes:
        # Group Policy infrastructure legitimately writes ZoneMap during logon
        Image|endswith:
            - '\gpscript.exe'    # GP startup/logon script engine
            - '\svchost.exe'     # GP client service processing
            - '\mmc.exe'         # Group Policy Management Console
    condition: (1 of selection_*) and not filter_gpo_processes
fields:
    - Image
    - TargetObject
    - Details
    - User
    - ProcessId
falsepositives:
    - Enterprise IT adding internal or partner domains to Trusted Sites via script
    - Software installers adding their own domains to Trusted Sites for functionality
    - Legacy enterprise applications that require Trusted Sites for ActiveX controls
    - SCCM/Intune configuration agents managing browser zone policies
level: medium

  Detects the addition of a domain to the Internet Explorer Trusted Sites zone via registry modifications.
  Attackers may abuse this technique to lower security restrictions for malicious domains,
  aiding in credential harvesting, drive‑by downloads, or stealthy C2 communication (e.g., over Office 365).
references:
  - https://github.com/redcanaryco/atomic-red-team/blob/f339e7da7d05f6057fdfcdd3742bfcf365fee2a9/atomics/T1112/T1112.md#atomic-test-4---add-domain-to-trusted-sites-zone

  - https://attack.mitre.org/techniques/T1112/
author: Security Analyst (Generated based on Atomic Red Team test)
date: 2026-05-26
tags:
  - attack.defense-evasion
  - attack.persistence
  - attack.t1112
logsource:
  product: windows
  category: registry_set
detection:
  selection_path:
    TargetObject|contains: '\Software\Microsoft\Windows\CurrentVersion\Internet Settings\ZoneMap\Domains\'
  selection_values:
    - Details: 'DWORD (0x00000002)'

  condition: selection_path and selection_values
