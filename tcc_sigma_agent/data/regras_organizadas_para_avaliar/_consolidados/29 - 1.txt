title: Suspicious Registry Run Key Modification
id: 8f7b6c5d-4e3f-4a2b-9c1d-0e1f2a3b4c5d
status: test
description: Detects the addition of an entry to a Registry Run key, a common method for establishing persistence on Windows systems. This technique is often used by malware and attackers to ensure their code runs automatically during user logon.
references:
  - https://github.com/last-byte/PersistenceSniper
  - https://www.microsoft.com/en-us/security/blog/2025/03/06/malvertising-campaign-leads-to-info-stealers-hosted-on-github/
  - https://github.com/redcanaryco/atomic-red-team/blob/5ede8f21e42ebe37e0a6eff757dba60bcfa85859/atomics/T1547.001/T1547.001.md
author: Sigma Rule Generator (based on research by Last-byte, Microsoft, and Red Canary)
date: 2026-06-04
tags:
  - attack.persistence
  - attack.t1547.001
  - attack.privilege-escalation
logsource:
  product: windows
  category: process_creation
detection:
  selection:
    Image|endswith: '\reg.exe'
    CommandLine|contains:
      - 'add'
    CommandLine|contains|all:
      - 'CurrentVersion\Run'
      - 'HKEY_CURRENT_USER\Software\Microsoft\Windows'
      - '/v'
  condition: selection
falsepositives:
  - Legitimate software installations or updates that automatically add entries to the Run key for proper functionality.
  - System administrators configuring startup applications.
level: medium

      - '\Software\Microsoft\Windows\CurrentVersion\Run\'

  condition: selection_runkeys

  - TargetObject
  - Details

  - Computer

  - Legitimate software auto-start configuration
  - Endpoint management and software deployment tools
  - User-installed applications that persist by design
level: high

# Arquivo: C.yml
title: Script Engine Launched from Startup Folder via Internet Shortcut - Storm-0408 Style Persistence
id: a92f4b17-3de1-4c80-b37e-9e2d0f8a65c3
status: experimental
description: |
    Detects wscript.exe or cscript.exe executing a script file (.js, .jse, .vbs, .vbe)
    where the script path resolves inside a Windows Startup folder, indicative of an
    internet shortcut (.url) or LNK-based persistence implant that survives user logon.

    This pattern was observed in the Storm-0408 malvertising campaign (December 2024),
    where a renamed AutoIT interpreter (.scr) was paired with a JavaScript file of the
    same name, and a .url internet shortcut placed in the user Startup folder pointed
    to that JavaScript file. On logon, Explorer resolves the .url and launches the .js
    via wscript.exe, which in turn executes the AutoIT payload for C2, browser credential
    theft, and DPAPI decryption.

    This technique is also covered by:
    - PersistenceSniper (Find-AllPersistence: detects script files in Startup folders
      as a persistence anomaly indicator).
    - Atomic Red Team T1547.001 tests #4 (vbs), #5 (jse), and #6 (bat): placing and
      executing script files from the Startup folder to achieve logon persistence.

    The combination of a script engine (wscript.exe) launched by explorer.exe where
    the command line points into AppData\Roaming\Microsoft\Windows\Start Menu\Programs\
    Startup or ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp is highly
    anomalous. Legitimate startup items are nearly always executables (.exe), shortcuts
    to executables (.lnk), or vendor-supplied scripts — not ad-hoc .js/.vbs/.jse files.

references:
    - https://www.microsoft.com/en-us/security/blog/2025/03/06/malvertising-campaign-leads-to-info-stealers-hosted-on-github/
    - https://github.com/last-byte/PersistenceSniper
    - https://github.com/redcanaryco/atomic-red-team/blob/5ede8f21e42ebe37e0a6eff757dba60bcfa85859/atomics/T1547.001/T1547.001.md
author: Generated from Microsoft Storm-0408 blog, PersistenceSniper, and Atomic Red Team T1547.001
date: 2025-03-06
tags:
    - attack.persistence
    - attack.t1547.001   # Boot or Logon Autostart Execution: Registry Run Keys / Startup Folder
    - attack.execution
    - attack.t1059.005   # Command and Scripting Interpreter: Visual Basic (VBScript)
    - attack.t1059.007   # Command and Scripting Interpreter: JavaScript
    - attack.defense_evasion
    - attack.t1036.005   # Masquerading: Match Legitimate Name or Location
    - tlp:white
logsource:
    product: windows
    category: process_creation
    # Requires Sysmon Event ID 1 or equivalent EDR process-create telemetry.
detection:
    # Script engine is the initiating process
    selection_script_engine:
        Image|endswith:
            - '\wscript.exe'
            - '\cscript.exe'

    # The script being executed lives inside a Startup folder
    # Covers both per-user (APPDATA) and all-users (ProgramData) paths
    selection_startup_path:
        CommandLine|contains:
            - '\Microsoft\Windows\Start Menu\Programs\Startup\'
            - '\Microsoft\Windows\Start Menu\Programs\StartUp\'

    # The script has a suspicious extension — these are not normal Startup items
    selection_script_extension:
        CommandLine|endswith:
            - '.js'
            - '.jse'
            - '.vbs'
            - '.vbe'
            - '.wsf'

    # Optionally tighten by parent: Explorer launches .url shortcuts on logon,
    # but an attacker's scheduled task or another process may also invoke these.
    # Commented out to avoid missing cases where the parent is cmd/powershell
    # calling the script explicitly post-installation.
    # filter_legitimate_parent:
    #     ParentImage|endswith: '\explorer.exe'

    # Exclude known vendor paths that legitimately use scripted startup items
    # (e.g. some AV products and management agents). Tune per environment.
    filter_known_legitimate:
        CommandLine|contains:
            - '\CyberArk\'
            - '\ManageEngine\'
            - '\Citrix\'

    condition: selection_script_engine and selection_startup_path and selection_script_extension and not filter_known_legitimate

falsepositives:
    - Legacy enterprise software that genuinely deploys VBScript or JScript files to
      the Startup folder as part of a managed configuration (uncommon post-2015).
    - IT automation frameworks (e.g. PDQ Deploy, Ansible Windows) that temporarily
      stage scripts in Startup during provisioning. These should be baseline-excluded
      by path or ParentImage (e.g. ParentImage ending in 'pdqdeploy.exe').
    - Developer workstations running Node or Deno toolchains that register .js helpers
      in Startup — validate CommandLine content against known tool signatures.
    # Recommended tuning: whitelist by CommandLine content for any known-good scripts
    # after reviewing your environment's baseline with PersistenceSniper.

level: high

# Arquivo: D.yml
title: Suspicious Creation of Common Windows Autostart Persistence Mechanisms
id: 6e2f9b1a-2026-persistence-sniper-detect
status: experimental
description: Detects creation or modification of common Windows autostart persistence mechanisms (registry Run keys, services, scheduled tasks, Startup folder LNKs/executables, AppInit_DLLs, Winlogon Shell) and use of common installer/utility binaries to create them. Useful for detecting commodity persistence frameworks and attacker tooling such as PersistenceSniper and malvertising-delivered droppers that establish autostart. Tune allowlists for legitimate deployment and management tooling.
author: Detection Engineer
date: 2026-06-05
references:
  - https://github.com/last-byte/PersistenceSniper
  - https://www.microsoft.com/en-us/security/blog/2025/03/06/malvertising-campaign-leads-to-info-stealers-hosted-on-github/
  - https://github.com/redcanaryco/atomic-red-team/blob/5ede8f21e42ebe37e0a6eff757dba60bcfa85859/atomics/T1547.001/T1547.001.md
logsource:
  product: windows
  service: sysmon
  category: persistence
detection:
  selection_registry_run_create:
    EventID: 13
    TargetObject|re:
      - '(?i)\\Software\\Microsoft\\Windows\\CurrentVersion\\Run(Once)?\\'
      - '(?i)\\Software\\Microsoft\\Windows\\CurrentVersion\\RunServices(Once)?\\'
      - '(?i)\\Software\\Wow6432Node\\Microsoft\\Windows\\CurrentVersion\\Run\\'
      - '(?i)\\SYSTEM\\CurrentControlSet\\Services\\.*'
      - '(?i)\\Software\\Microsoft\\Windows NT\\CurrentVersion\\Windows\\AppInit_DLLs'
      - '(?i)\\Software\\Microsoft\\Windows NT\\CurrentVersion\\Winlogon\\Shell'
  selection_startup_file_create:
    EventID: 11
    TargetFilename|re:
      - '(?i)\\Users\

\[^\\]

+\\AppData\\Roaming\\Microsoft\\Windows\\Start Menu\\Programs\\Startup\\'
      - '(?i)\\ProgramData\\Microsoft\\Windows\\Start Menu\\Programs\\Startup\\'
    TargetFilename|re_any:
      - '\.lnk$'
      - '\.exe$'
      - '\.ps1$'
      - '\.bat$'
  selection_service_install:
    EventID: 7045
  selection_schtasks_create:
    EventID: 4698
  selection_common_tools:
    EventID: 1
    Image|re:
      - '(?i)\\(reg\.exe|regsvr32\.exe|schtasks\.exe|sc\.exe|powershell\.exe|pwsh\.exe|cmd\.exe|mshta\.exe|rundll32\.exe)$'
    CommandLine|re:
      - '(?i)\b(create|create\s+service|/create|/create\s+service|/register|/create:|/s create|/create /tn|/create /sc)\b'
  selection_download_from_github:
    EventID: 1
    CommandLine|re:
      - '(?i)(curl|wget|bitsadmin|certutil|Invoke-WebRequest|Invoke-RestMethod).*github\.com'
  condition: (selection_registry_run_create or selection_startup_file_create or selection_service_install or selection_schtasks_create) and (selection_common_tools or selection_download_from_github or selection_registry_run_create)
fields:
  - timestamp
  - EventID
  - ComputerName
  - SubjectUserName
  - Image
  - ParentImage
  - CommandLine
  - TargetObject
  - TargetFilename
  - ProcessId
falsepositives:
  - Legitimate software deployment, patching, or management tools creating services, scheduled tasks, or registry run keys (whitelist known management servers and service accounts).
  - User-installed applications that register autostart entries intentionally.
level: high
tags:
  - attack.persistence
  - attack.t1547
  - attack.t1547.001
  - malware.persistence
  - detection.windows.sysmon
notes: |
  - Tuning: add allowlists for known deployment/orchestration tools (SCCM, Intune, vendor installers, CI/CD runners) and known admin accounts.
  - Investigation: collect full command lines, parent/child process trees, file hashes of created binaries/LNKs, scheduled task XML, service binary paths, registry value contents, and any download URLs; search for other hosts with similar indicators.
  - Response: remove unauthorized autostart entries, revoke credentials if abuse is confirmed, and perform a broader hunt for related tooling or lateral movement.

# Arquivo: E.yml
title: File Creation in Windows Startup Folder for Persistence
id: 1bf425f1-bd12-40cf-a7bb-db169d06b45a
status: experimental
description: Detects the creation or modification of shortcut files (.lnk), executables, or script files within Windows Startup directories. Threat actors frequently drop payloads or shortcuts into these folders to establish persistence (MITRE T1547.001), ensuring malicious code runs automatically upon user logon. This mechanism is frequently tracked by persistence hunting tools like PersistenceSniper and was prominently utilized in the March 2025 malvertising campaign distributing info-stealers via GitHub.
references:
    - https://github.com/last-byte/PersistenceSniper
    - https://www.microsoft.com/en-us/security/blog/2025/03/06/malvertising-campaign-leads-to-info-stealers-hosted-on-github/
    - https://github.com/redcanaryco/atomic-red-team/blob/5ede8f21e42ebe37e0a6eff757dba60bcfa85859/atomics/T1547.001/T1547.001.md
author: Security Operations Center
date: 2026/06/05
tags:
    - attack.persistence
    - attack.t1547.001 # Boot or Logon Autostart Execution: Registry Run Keys / Startup Folder
logsource:
    category: file_event
    product: windows
detection:
    selection_path:
        TargetFilename|contains: '\Microsoft\Windows\Start Menu\Programs\Startup\'
    selection_extensions:
        TargetFilename|endswith:
            - '.lnk'
            - '.exe'
            - '.bat'
            - '.cmd'
            - '.vbs'
            - '.vbe'
            - '.js'
            - '.ps1'
            - '.com'
            - '.scr'
            - '.msi'
    condition: all of selection_*
falsepositives:
    - Legitimate software installers (e.g., communication tools, cloud storage synchronization clients) establishing authorized startup shortcuts.
    - System administrators or end users manually configuring programs to start automatically on boot.
level: medium
