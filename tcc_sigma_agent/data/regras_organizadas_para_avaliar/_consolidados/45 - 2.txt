# Arquivo: B.yml
title: MSBuild Initiated Outbound Network Connections to HTTP/HTTPS Ports
id: 7c5d2e1f-3b4a-4c6e-9d8f-0a1b2c3d4e5f
status: experimental
description: Detects network connections initiated by msbuild.exe to standard web ports (HTTP/HTTPS). MSBuild is a signed Microsoft binary that has been abused by adversaries (e.g., SilentTrinity) to execute attacker-controlled payloads and perform C2 communications while bypassing application allow-lists. Outbound connections from msbuild.exe to common web ports are highly suspicious and warrant investigation.
author: Senior Threat Detection Engineer
date: 2026/06/13
references:
  - [https://www.blackhillsinfosec.com/my-first-joyride-with-silenttrinity/](https://www.blackhillsinfosec.com/my-first-joyride-with-silenttrinity/)
tags:
  - attack.command_and_control
  - defense_evasion
  - living-off-the-land
  - windows
logsource:
  product: windows
  category: network_connection
  description: Network connection logs that include the initiating process image (InitiatingProcessImage or ProcessImage), destination IP/port, and connection direction. Ensure outbound/egress connections are captured.
detection:
  selection:
    InitiatingProcessImage|endswith:
      - '\\msbuild.exe'
      - '\\MSBuild.exe'
      - '\\msbuild\\msbuild.exe'
  filter:
    DestinationPort|in:
      - 80
      - 443
      - 8080
      - 8443
    Direction|in:
      - 'outbound'
      - 'egress'
      - 'initiated'
  condition: selection and filter
fields:
  - InitiatingProcessImage
  - ProcessId
  - SourceIp
  - DestinationIp
  - DestinationPort
  - Direction
  - Protocol
falsepositives:
  - Legitimate build servers or CI/CD systems that perform HTTP/HTTPS requests during build or restore operations using msbuild.
  - Developer machines invoking msbuild which contact package repositories or artifact servers.
level: high

# Arquivo: D.yml
title: MSBuild Outbound Network Connection to HTTP or HTTPS Port
id: 7e1f4b2c-3d9a-4e8f-b6c1-5a3d2e7f1b48
status: experimental
description: >
  Detects outbound network connections initiated by MSBuild.exe to standard
  HTTP and HTTPS ports. MSBuild is a signed Microsoft build-automation binary
  that supports inline task execution via XML project files, allowing
  arbitrary managed code to be compiled and executed in-process without
  writing a payload to disk. SilentTrinity and similar C2 frameworks abuse
  this capability to achieve application allow-list bypass by hosting a
  malicious MSBuild project file on attacker infrastructure and invoking
  MSBuild directly. Because the payload executes within the MSBuild process,
  the resulting C2 beacon traffic appears to originate from a trusted,
  signed Microsoft binary. MSBuild has no legitimate operational need to
  initiate outbound HTTP or HTTPS connections in a production environment;
  its normal function is local build orchestration. Any outbound connection
  on port 80 or 443 from MSBuild.exe should be treated as a high-confidence
  indicator of abuse and investigated immediately.
references:
  - https://www.blackhillsinfosec.com/my-first-joyride-with-silenttrinity/
author: Senior Threat Detection Engineer
date: 2026-05-25
tags:
  - attack.defense_evasion
  - attack.execution
  - attack.t1127.001
  - attack.t1071.001
logsource:
  category: network_connection
  product: windows
detection:
  selection:
    Image|endswith: '\MSBuild.exe'
    Initiated: 'true'
    DestinationPort:
      - 80
      - 443
  filter:
    DestinationIp|startswith:
      - '127.'
      - '::1'
  condition: selection and not filter
falsepositives:
  - Developer workstations where MSBuild legitimately retrieves NuGet
    packages or communicates with an internal package feed or build
    orchestration service during a genuine software build workflow.
    Detection should be suppressed or contextualised on dedicated build
    agents where such activity is expected and the destination IP ranges
    of internal package repositories are known.
level: high
