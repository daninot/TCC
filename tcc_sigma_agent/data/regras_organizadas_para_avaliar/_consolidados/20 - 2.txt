# Arquivo: C.yml
title: Kubernetes Secret Created Modified or Deleted
id: 2b9e4f7c-1a3d-4e8b-b6f4-3c7a1e5d8b29
status: experimental
description: >
  Detects mutating API operations targeting Kubernetes Secret objects as
  recorded in the API server audit log. Kubernetes Secrets store sensitive
  values including service account tokens, TLS private keys, container
  registry credentials, and application secrets mounted into pods at runtime.
  An adversary who has obtained sufficient RBAC permissions — through a
  compromised service account, a stolen kubeconfig, or privilege escalation —
  may create new secrets to persist credentials or plant malicious values
  that will be consumed by workloads; patch or replace existing secrets to
  alter application behaviour, inject environment variables into future pod
  launches, or overwrite TLS material; or delete secrets to disrupt services
  or destroy evidence of prior credential access. All four mutating verbs
  (create, update, patch, delete) are included because each represents a
  distinct abuse scenario: creation for persistence, update and patch for
  tampering, and deletion for impact or cover-up. The detection targets the
  secrets resource across all API groups and namespaces, providing broad
  coverage without requiring namespace-specific tuning.
references:
  - https://kubernetes.io/docs/reference/config-api/apiserver-audit.v1/
  - https://commandk.dev/blog/guide-to-audit-k8s-secrets-for-compliance/
author: Senior Threat Detection Engineer
date: 2026-05-25
tags:
  - attack.credential_access
  - attack.persistence
  - attack.impact
  - attack.t1552.007
  - attack.t1485
logsource:
  product: kubernetes
  service: audit
detection:
  selection:
    objectRef.resource: secrets
    verb:
      - create
      - update
      - patch
      - delete
  condition: selection
falsepositives:
  - Kubernetes operators, controllers, and admission webhooks that
    programmatically manage secrets as part of their normal reconciliation
    loop, such as cert-manager rotating TLS certificates or external-secrets
    synchronising values from a remote secrets store.
  - CI/CD pipelines that create, update, or delete deployment secrets
    as part of an approved release workflow.
  - Platform engineering or SRE teams performing authorised secret
    rotation or clean-up as part of a documented credential management
    procedure.
level: medium
