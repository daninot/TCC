# Arquivo: A.yml
title: Suspicious Application Authentication Flow in Microsoft Entra
id: 9f8a7b2c-4d1e-11ef-9a2d-0242ac120002
status: experimental
description: Detects applications using insecure or unusual authentication flows (e.g., ROPC or client secrets) in Microsoft Entra audit logs.
author: Copilot
date: 2026/05/25
references:
  - https://learn.microsoft.com/en-us/entra/architecture/security-operations-applications#application-authentication-flows
logsource:
  product: azure
  service: entra
  category: authentication
detection:
  selection_insecure_flows:
    AuthenticationFlow|contains:
      - "ROPC"
      - "client_secret"
  selection_expected_flows:
    AuthenticationFlow|contains:
      - "certificate"
      - "managed_identity"
      - "client_assertion"
  condition: selection_insecure_flows and not selection_expected_flows
fields:
  - timestamp
  - AuthenticationFlow
  - ApplicationId
  - ApplicationName
  - UserPrincipalName
  - IPAddress
falsepositives:
  - Legacy applications that cannot yet migrate to secure flows
level: high
tags:
  - attack.defense_evasion
  - attack.t1556.003

# Arquivo: B.yml
title: Microsoft Entra - Successful Sign-in via ROPC Authentication Flow
id: 8f4c2b1e-9a73-4d85-b062-e317f95c4831
status: test
description: |
    Detects a successful sign-in using the Resource Owner Password
    Credentials (ROPC) OAuth 2.0 flow against Microsoft Entra ID.
    In this flow the application receives the user's plaintext password
    and submits it directly to the identity provider, bypassing MFA
    and Conditional Access policies. Microsoft explicitly discourages
    ROPC outside of automated integration testing. Presence in
    production may indicate a misconfigured or malicious application
    harvesting user credentials or performing password spraying.
references:
    - https://learn.microsoft.com/en-us/entra/architecture/security-operations-applications#application-authentication-flows
    - https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth-ropc
author: Security Team
date: 2026-05-25
tags:
    - attack.credential_access
    - attack.t1078.004   # Valid Accounts: Cloud Accounts
    - attack.t1110.003   # Brute Force: Password Spraying
    - attack.t1556.006   # Modify Auth Process: MFA bypass vector
logsource:
    product: azure
    service: signinlogs
detection:
    selection:
        AuthenticationProtocol|contains: 'ropc'
        ResultType: 0
    filter_testing:
        # Suppress known CI/CD service accounts used for automated testing
        UserPrincipalName|endswith:
            - '@testing.yourdomain.com'
    condition: selection and not filter_testing
fields:
    - UserPrincipalName
    - AppDisplayName
    - AppId
    - IPAddress
    - Location
    - AuthenticationProtocol
    - ResultType
    - DeviceDetail
    - ConditionalAccessStatus
falsepositives:
    - Automated integration testing pipelines (only valid ROPC use case)
    - Legacy applications not yet migrated to auth code flow with PKCE
    - CI/CD service accounts performing non-interactive authentication
level: medium

# Arquivo: C.yml
title: Microsoft Entra Application Authentication Flow Failure
id: 4b2c12ef-83d1-4cb5-8845-de065fa89622
status: experimental
description: Detects failed application authentication flows within Microsoft Entra ID (Azure AD). This includes attempts to authenticate via service principals using invalid, expired, or incorrect client secrets and certificates, which can indicate brute-forcing, credential stuffing, or leaked old configuration files being misused by an adversary.
references:
    - https://learn.microsoft.com/en-us/entra/architecture/security-operations-applications#application-authentication-flows
    - https://login.microsoftonline.com/error
author: Security Operations Center
date: 2026/05/25
tags:
    - attack.credential_access
    - attack.t1110.001 # Brute Force: Password Guessing
    - attack.t1078.004 # Valid Accounts: Cloud Accounts
logsource:
    product: azure
    service: signinlogs
detection:
    selection:
        # Category can be SignInLogs or ServicePrincipalSignInLogs depending on SIEM ingestion schema
        ResultType:
            - '7000215' # Invalid client secret is provided
            - '700027'  # Client certificate is missing, invalid, or improperly configured
            - '7000222' # The provided client secret keys are expired
            - '700023'  # Client certificate has been revoked
    condition: selection
falsepositives:
    - Misconfigured internal applications, scripts, or automated deployment pipelines (e.g., CI/CD) using outdated secrets or expired certificates after a credential rotation cycle.
level: medium

# Arquivo: D.yml
title: Microsoft Entra Suspicious Service Principal Authentication Flow
id: 6b3a8b2d-4a31-4f77-9e11-2f5d3a0c9f71
status: experimental
description: >
  Detects Microsoft Entra ID service principal sign-ins using OAuth
  application authentication flows such as client credentials or
  certificate-based authentication from unexpected or external IP ranges.
  This may indicate compromised application credentials, abused app
  registrations, or unauthorized automation activity.
references:
  - https://learn.microsoft.com/en-us/entra/architecture/security-operations-applications#application-authentication-flows
  - https://learn.microsoft.com/en-us/entra/identity/monitoring-health/concept-service-principal-sign-ins
author: OpenAI
date: 2026-05-25
tags:
  - attack.persistence
  - attack.credential_access
  - attack.t1550
  - attack.t1550.001
  - attack.cloud
logsource:
  product: azure
  service: entra-id
detection:
  selection_event_type:
    signInEventTypes|contains: "servicePrincipal"
  selection_auth_flow:
    clientAppUsed:
      - "Client Credentials"
      - "Managed Identity"
      - "Workload Identity Federation"
  filter_internal_ranges:
    ipAddress:
      - "10.*"
      - "172.16.*"
      - "172.17.*"
      - "172.18.*"
      - "172.19.*"
      - "172.20.*"
      - "172.21.*"
      - "172.22.*"
      - "172.23.*"
      - "172.24.*"
      - "172.25.*"
      - "172.26.*"
      - "172.27.*"
      - "172.28.*"
      - "172.29.*"
      - "172.30.*"
      - "172.31.*"
      - "192.168.*"
  condition: selection_event_type and selection_auth_flow and not filter_internal_ranges
fields:
  - appDisplayName
  - appId
  - servicePrincipalId
  - ipAddress
  - resourceDisplayName
  - clientAppUsed
  - authenticationProtocol
  - conditionalAccessStatus
  - status.failureReason
falsepositives:
  - Legitimate third-party SaaS integrations
  - Cloud-hosted automation platforms
  - Authorized DevOps pipelines authenticating externally
level: high
