# Arquivo: B.yml
title: Windows PowerShell - Invoke-Obfuscation TOKEN COMMAND Format String Reorder
id: 8b5b6f2a-4c91-4e57-a081-3d7e8c4b9f25
status: experimental
description: |
    Detects PowerShell command-name obfuscation using the Format String Reorder
    technique (TOKEN\COMMAND\3, TOKEN\ARGUMENT\4, TOKEN\MEMBER\4, TOKEN\TYPE\2,
    TOKEN\ALL) generated by Invoke-Obfuscation, as documented in SigmaHQ
    community collaboration issue #1009.

    Invoke-Obfuscation uses the PowerShell -f operator with out-of-order indices
    to reconstruct cmdlet names from fragments:
      "{3}{4}{2}{1}{0}{5}" -f 'o','essi','pr','Invo','ke-Ex','n' → Invoke-Expression

    Detection key: THREE OR MORE consecutive {N} format groups immediately
    adjacent to each other in a string, followed by the -f operator.
    Legitimate PowerShell rarely produces 3+ adjacent non-sequential {N} groups
    for the purpose of reconstructing function or cmdlet names.

    This is the first Sigma rule targeting the reorder pattern specifically.
    Complement with the existing Bohannon IEX obfuscation rules ($PSHome,
    $ShellId, $env:Public, $env:ComSpec, $VerbosePreference patterns).
references:
    - https://github.com/SigmaHQ/sigma/issues/1009
    - https://github.com/danielbohannon/Invoke-Obfuscation
    - https://www.danielbohannon.com/blog-1/2017/12/2/the-invoke-obfuscation-usage-guide
    - https://attack.mitre.org/techniques/T1027/010/
    - https://attack.mitre.org/techniques/T1059/001/
author: Security Team (SigmaHQ Issue #1009 community contribution)
date: 2026-05-25
tags:
    - attack.defense_evasion
    - attack.t1027         # Obfuscated Files or Information
    - attack.t1027.010     # Command Obfuscation
    - attack.execution
    - attack.t1059.001     # Command and Scripting Interpreter: PowerShell
logsource:
    category: process_creation
    product: windows
detection:
    selection_format_reorder:
        # Regex: quote followed by 3+ adjacent {N} format specifiers, then quote, then -f
        # Matches: "{3}{4}{2}{1}{0}{5}"-f '...' (TOKEN\COMMAND\3)
        # Matches: "{0}{3}{2}{1}{4}" -f '...' (TOKEN\ALL)
        # Does NOT match "{0}{1}"-f (only 2 groups — common in legitimate code)
        CommandLine|re: '["'']\{\d+\}\{\d+\}\{\d+\}["'']\s*-[fF]'
    condition: selection_format_reorder
fields:
    - CommandLine
    - Image
    - ParentImage
    - User
    - ParentCommandLine
falsepositives:
    - Legitimate scripts using 3+ adjacent format specifiers for string construction
      (rare in production; investigate regardless — the pattern is highly suspicious)
    - Custom obfuscation tools producing a similar format string pattern
    - Automated test frameworks generating complex PowerShell format strings
level: high

title: PowerShell Invoke-Obfuscation Via Environment Variable String Concat
id: bd170a41-2a62-4ef8-be58-3d1f34b22c71
status: test
description: Detects highly specific PowerShell process execution command-line patterns generated by the Invoke-Obfuscation framework. Specifically, it identifies the character array indexing and string concatenation of default environment variables (like ComSpec or Public) or standard engine variables (such as $pshome and $shellid) to assemble and blindly execute masked commands (e.g., reassembling 'iex').
references:
    - https://github.com/SigmaHQ/sigma/issues/1009
    - https://www.danielbohannon.com/blog-1/2016/9/25/invoke-obfuscation-deriving-consequences-from-execution
author: Security Operations Center
date: 2020/09/14
modified: 2026/06/04
tags:
    - attack.defense_evasion
    - attack.execution
    - attack.t1027.005 # Obfuscated Files or Information: Indicator Removal from Tools
    - attack.t1059.001 # Command and Scripting Interpreter: PowerShell
logsource:
    product: windows
    category: process_creation
detection:
    selection_images:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_regex_patterns:
        # Regex modifiers match lowercase equivalents generated by Invoke-Obfuscation workflows
        CommandLine|re:
            - '.*\$pshome\[\s*\d{1,3}\s*\]\s*\+\s*\$pshome\['
            - '.*\$shellid\[\s*\d{1,3}\s*\]\s*\+\s*\$shellid\['
            - '.*\$env:public\[\s*\d{1,3}\s*\]\s*\+\s*\$env:public\['
            - '.*\$env:comspec\[(\s*\d{1,3}\s*,){2}'
    condition: all of selection_*
falsepositives:
    - Highly specialized administrative deployment workflows or legacy provisioning scripts that deliberately isolate or dynamically index shell variables to derive application execution frameworks (rare).
level: high

# Arquivo: D.yml
title: Invoke-Obfuscation Obfuscated IEX Invocation
id: 4bf943c6-5146-4273-98dd-e958fd1e3abf
status: experimental
description: Detects obfuscated PowerShell IEX invocation patterns generated by the Invoke-Obfuscation framework by matching command-line regex variants that break up the IEX invocation and use indexed string concatenation.
author: Detection Engineer
date: 2026-06-04
references:
  - "https://github.com/SigmaHQ/sigma/issues/1009" 
logsource:
  product: windows
  service: process_creation
  category: process_creation
detection:
  selection_powershell:
    Image|endswith:
      - "\\powershell.exe"
      - "\\pwsh.exe"
    CommandLine|re:
      - '\$PSHome

\[\s*\d{1,3}\s*\]

\s*\+\s*\$PSHome

\['
      - '\$ShellId

\[\s*\d{1,3}\s*\]

\s*\+\s*\$ShellId

\['
      - 'IEX\s*\(\s*\$\(.*\)\s*\)'
      - 'IEX\s*\+\s*.*IEX'
      - 'Invoke-Expression\s*\(\s*\$\(.*\)\s*\)'
  selection_encoded:
    CommandLine|re:
      - '-EncodedCommand\s+[A-Za-z0-9+/=]{80,}'
      - '\-enc\s+[A-Za-z0-9+/=]{80,}'
  condition: selection_powershell or selection_encoded
fields:
  - timestamp
  - ComputerName
  - User
  - Image
  - CommandLine
  - ParentImage
  - ProcessId
falsepositives:
  - Legitimate administrative scripts that intentionally use complex string indexing or very long base64 encoded commands (whitelist known automation accounts).
  - Security tooling or red‑team engagements using Invoke-Obfuscation for testing (track and whitelist test accounts/environments).
level: high
tags:
  - attack.defense_evasion
  - attack.t1027
  - tool.invoke-obfuscation
