  - https://speakerdeck.com/heirhabarov/hunting-for-powershell-abuse?slide=65

  - attack.defense-evasion

        - '\powershell.exe'
        - '\pwsh.exe'

        - 'PowerShell.EXE'
        - 'pwsh.dll'

    CommandLine|contains:
      - 'ToInt'
      - 'ToDecimal'
      - 'ToByte'
      - 'ToUint'
      - 'ToSingle'
      - 'ToSByte'
  selection_to_2:
    CommandLine|contains:
      - 'ToChar'
      - 'ToString'
      - 'String'
  selection_gen_1:
    CommandLine|contains|all:
      - 'char'
      - 'join'
  selection_gen_2:
    CommandLine|contains|all:
      - 'split'
      - 'join'
  condition: selection_img and (all of selection_to_* or 1 of selection_gen_*)
falsepositives:
  - Unknown
level: low

# Arquivo: B.yml
title: Suspicious PowerShell Abuse Indicators
id: 7a3f2d9e-1b6c-4f2a-9d8e-0c1b2a3d4e5f
status: experimental
description: Detects common PowerShell abuse patterns used by attackers (encoded commands, IEX/Invoke-Expression stagers, execution policy bypass, download cradles, obfuscation patterns, and suspicious parent processes). Based on hunting guidance for PowerShell abuse.
author: Detection Engineer
date: 2026-06-06
references:
  - https://speakerdeck.com/heirhabarov/hunting-for-powershell-abuse
logsource:
  product: windows
  service: sysmon
  category: process_creation
detection:
  selection_powershell_process:
    Image|endswith:
      - "\\powershell.exe"
      - "\\pwsh.exe"
      - "\\powershell_ise.exe"
    EventID: 1
  selection_encoded_command:
    CommandLine|re:
      - '(?i)-EncodedCommand\s+[A-Za-z0-9+/=]{80,}'
      - '(?i)-enc\s+[A-Za-z0-9+/=]{80,}'
  selection_bypass_flags:
    CommandLine|re:
      - '(?i)(-NoProfile|-NonInteractive|-ExecutionPolicy\s+Bypass|-ExecutionPolicy\s+Unrestricted|-WindowStyle\s+Hidden)'
  selection_iex_invoke:
    CommandLine|re:
      - '(?i)\b(IEX|Invoke-Expression)\b'
      - '(?i)IEX\s*\(\s*\$\(.*\)\s*\)'
  selection_download_cradle:
    CommandLine|re:
      - '(?i)(Invoke-WebRequest|Invoke-RestMethod|Start-BitsTransfer|bitsadmin|certutil|curl|wget).*http'
      - '(?i)(New-Object\s+System\.Net\.WebClient|DownloadString|DownloadFile)\('
  selection_obfuscation_patterns:
    CommandLine|re:
      - '(?i)(FromBase64String|ToCharArray\(\)|\$\w+

\[\d+\]

\s*\+\s*\$\w+

\[\d+\]

)'
      - '(?i)(-join\s+\(.*\))'
      - '(?i)(Invoke-Obfuscation|Invoke-ReflectivePEInjection|PowerSploit|Obfuscation)'
  selection_suspicious_parent:
    ParentImage|re:
      - '(?i)\\(winword|excel|powerpnt|outlook|acrord32|wordpad|explorer)\.exe$'
  selection_amsi_bypass_indicators:
    CommandLine|re:
      - '(?i)(amsi|AmsiScanBuffer|Patch|BypassAmsi|Disable-Amsi)'
  condition: selection_powershell_process and (selection_encoded_command or selection_bypass_flags or selection_iex_invoke or selection_download_cradle or selection_obfuscation_patterns or selection_amsi_bypass_indicators or selection_suspicious_parent)
fields:
  - timestamp
  - EventID
  - ComputerName
  - SubjectUserName
  - Image
  - ParentImage
  - CommandLine
  - ProcessId
falsepositives:
  - Legitimate administrative automation, scheduled tasks, or management scripts that use encoded commands or bypass flags (whitelist known automation accounts and servers).
  - Security tooling and red-team exercises that intentionally use obfuscation or encoded payloads (maintain allowlist for test environments).
level: high
tags:
  - attack.execution
  - attack.defense_evasion
  - attack.initial_access
  - detection.powershell
notes: |
  - Tune by whitelisting known automation/service accounts and CI/CD runners.
  - Investigate by collecting full command lines, parent/child process trees, any downloaded artifacts, network connections, and AMSI/ETW telemetry; search for similar command lines across the estate.
  - Consider correlating with script block logging, module loads, and PowerShell transcription logs to increase fidelity.

# Arquivo: D.yml
title: Fileless .NET Assembly Loaded from Registry Key via Reflection
id: e51b3c92-f784-4d0a-b16e-2a9f7c08e4d3
status: experimental
description: |
    Detects a PowerShell technique where a .NET assembly (DLL) is stored as a
    base64-encoded value inside a registry key and subsequently loaded into the
    current PowerShell process via [Reflection.Assembly]::Load() after being
    retrieved with Get-ItemProperty.

    This technique achieves fully fileless execution: no DLL is ever written to
    disk. The assembly lives in the registry (typically under an obscure
    HKCU:\Software\Classes\<random> key), is read into a byte array via
    [System.Convert]::FromBase64String(), and loaded directly into memory.
    Arbitrary exported methods are then invoked via [Namespace.Class]::Method().

    Example payload (from Kheirkhabarov OffZone 2019, slide 47):
        powershell -command "
          [Reflection.Assembly]::Load(
            [System.Convert]::FromBase64String(
              (Get-ItemProperty 'HKCU:\Software\Classes\UBZZXDJZAOGD').b64encAssembly
            )
          );
          [CMD_exec.Class1]::RunCMD()"

    A variant without base64 reads the raw bytes directly:
        [Reflection.Assembly]::Load(
          [System.IO.File]::ReadAllBytes(
            (Get-ItemProperty 'HKCU:\Software\Classes\<key>').binAssembly
          )
        )

    Detection relies on observing the co-occurrence of:
      1. Reflection.Assembly / Assembly::Load  — loads arbitrary .NET code
      2. Get-ItemProperty / gp                  — reads the payload from registry
    in the same PowerShell command line or Script Block text.
    This triple is documented as empirically unique to malicious usage; no
    legitimate framework combines registry property reads with runtime
    assembly loading in this way.

    The same command-line pattern surfaces across five event types documented
    by Kheirkhabarov as unified command-line sources:
      - Sysmon EID 1  (process creation, CommandLine field)
      - WEL EID 4688  (process creation with command-line audit)
      - WEL EID 7045  (service installation, ImagePath field)
      - WEL EID 4698  (scheduled task creation, task action field)
      - Sysmon EID 13 (registry value set, Details field — when persisted as ASEP)
      - PS  EID 4104  (Script Block Logging, ScriptBlockText field)

references:
    - https://speakerdeck.com/heirhabarov/hunting-for-powershell-abuse
    - https://files.speakerdeck.com/presentations/a000f3919abd489096050e22f60d2ccd/Kheirkhabarov_OffZone2019_final.pdf
author: Generated from Teymur Kheirkhabarov — "Hunting for PowerShell Abuse", OffZone 2019 (BI.ZONE)
date: 2019-06-17
tags:
    - attack.execution
    - attack.t1059.001   # Command and Scripting Interpreter: PowerShell
    - attack.defense_evasion
    - attack.t1027       # Obfuscated Files or Information
    - attack.t1620       # Reflective Code Loading
    - attack.persistence
    - attack.t1547.001   # Boot or Logon Autostart Execution: Registry Run Keys (payload staging)
    - tlp:white
logsource:
    product: windows
    category: ps_script
    # Primary source: PowerShell Script Block Logging (EID 4104).
    # Covers deobfuscated, runtime-decoded content that command-line matching misses.
    # A companion rule targeting process_creation (EID 1 / 4688) should be created
    # to cover cases where Script Block Logging is absent or disabled.
detection:
    # The payload is retrieved from the registry
    selection_registry_read:
        ScriptBlockText|contains:
            - 'Get-ItemProperty'
            - ' gp '                 # Built-in alias for Get-ItemProperty

    # The retrieved bytes are loaded as a .NET assembly at runtime
    selection_assembly_load:
        ScriptBlockText|contains:
            - 'Reflection.Assembly'
            - '[System.Reflection.Assembly]'

    selection_load_method:
        ScriptBlockText|contains:
            - '::Load('
            - '::LoadFrom('
            - '::LoadFile('

    # Tighten to avoid hitting legitimate admin scripts that happen to combine
    # registry reads with assembly loads for unrelated reasons (very rare).
    # Require at least one base64 or byte-conversion indicator to confirm
    # the registry value is holding encoded binary data.
    selection_encoded_payload:
        ScriptBlockText|contains:
            - 'FromBase64String'
            - 'ReadAllBytes'
            - 'Convert]::From'

    condition: >
        selection_registry_read
        and selection_assembly_load
        and selection_load_method
        and selection_encoded_payload

falsepositives:
    - Highly unlikely in this exact combination. No known legitimate software
      reads a registry property, base64-decodes it, and loads the result as a
      .NET assembly at runtime.
    - Theoretically possible in advanced self-updating software that uses the
      registry as a byte store — validate by inspecting the specific registry
      key path and the loaded assembly's metadata in the Script Block log.
    - Custom internal tooling in software development environments that
      experiments with reflection-based plugin loading from non-standard stores.
      Exclude by ParentImage (e.g. Visual Studio devenv.exe) if needed.
level: critical

# Arquivo: E.yml
title: Suspicious PowerShell Abbreviated Command Line Arguments
id: e4b25e71-460d-45df-91bf-cb99cf80cf1e
status: experimental
description: Detects the use of highly abbreviated or concatenated command-line arguments in PowerShell execution (such as '-w h', '-ep bypass', or '-nop'). Threat actors commonly use these shortened parameters to bypass legacy string-matching security controls, minimize command length, or obfuscate the true nature of script execution.
references:
    - https://speakerdeck.com/heirhabarov/hunting-for-powershell-abuse
author: Security Operations Center
date: 2026/06/05
tags:
    - attack.execution
    - attack.defense_evasion
    - attack.t1059.001 # Command and Scripting Interpreter: PowerShell
logsource:
    product: windows
    category: process_creation
detection:
    selection_image:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_abbreviated_flags:
        CommandLine|contains:
            - ' -w h'          # Short for -WindowStyle Hidden
            - ' -win h'        # Short for -WindowStyle Hidden
            - ' -windowh'      # Truncated windowstyle
            - ' -window s'     # Short for -WindowStyle Swapped/Secret/Stream
            - ' -nop '         # Short for -NoProfile
            - ' -noni '        # Short for -NonInteractive
            - ' -ep '          # Short for -ExecutionPolicy
            - ' -exec b'       # Short for -ExecutionPolicy Bypass
            - ' -encodedc'     # Truncated -EncodedCommand
    condition: selection_image and selection_abbreviated_flags
falsepositives:
    - Legacy corporate login scripts or automated IT administrative wrappers that utilize aggressive shorthand parameters to conserve buffer sizes.
    - Third-party endpoint management agents or software deployment frameworks (e.g., SCCM, Tanium, Kaseya) launching internal provisioning functions.
level: medium
