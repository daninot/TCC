title: System Binary Copied To Unusual Location (Masquerading / T1036)
id: 3b9f1d2e-2026-windows-system-file-copied-unusual-location
status: experimental
description: Detects creation or placement of common Windows system binaries (e.g., svchost.exe, lsass.exe, cmd.exe, powershell.exe, explorer.exe, services.exe) outside of expected system directories. Attackers often copy legitimate system files to user-writable or non-standard locations to masquerade malicious payloads or evade detection (Atomic Test: system file copied to unusual location). Tune allowlists for legitimate software deployment and developer activity.
author: Detection Engineer
date: 2026-06-08
references:
  - https://twitter.com/ffforward/status/1481672378639912960
  - https://github.com/redcanaryco/atomic-red-team/blob/f339e7da7d05f6057fdfcdd3742bfcf365fee2a9/atomics/T1036/T1036.md#atomic-test-1---system-file-copied-to-unusual-location
logsource:
  product: windows
  service: sysmon
  category: file_event
detection:
  selection_system_binaries_created:
    EventID: 11
    TargetFilename|re:
      - '(?i)\\(svchost|lsass|lsm|services|winlogon|explorer|cmd|powershell|pwsh|rundll32|taskhostw|conhost|wuauclt|mshta|regsvr32)\.(exe|dll)$'
  selection_expected_system_paths:
    TargetFilename|not_re:
      - '(?i)\\Windows\\System32\\'
      - '(?i)\\Windows\\SysWOW64\\'
      - '(?i)\\Program Files\\'
      - '(?i)\\Program Files \(x86\)\\'
      - '(?i)\\Windows\\winsxs\\'
  selection_user_writable_locations:
    TargetFilename|re:
      - '(?i)\\Users\

\[^\\]

+\\AppData\\Local\\'
      - '(?i)\\Users\

\[^\\]

+\\AppData\\Roaming\\'
      - '(?i)\\Users\

\[^\\]

+\\Downloads\\'
      - '(?i)\\Users\

\[^\\]

+\\Desktop\\'
      - '(?i)\\AppData\\Local\\Temp\\'
      - '(?i)\\ProgramData\\'
      - '(?i)\\Users\\Public\\'
      - '(?i)\\.*\\Startup\\'
  selection_copy_tools_process:
    EventID: 1
    Image|re:
      - '(?i)\\(cmd\.exe|powershell\.exe|pwsh\.exe|xcopy\.exe|robocopy\.exe|copy\.exe|bitsadmin\.exe|certutil\.exe|bitsadmin\.exe|mshta\.exe)\$'
    CommandLine|re:
      - '(?i)\b(copy|xcopy|robocopy|bitsadmin|certutil|Invoke-WebRequest|Invoke-RestMethod|Start-BitsTransfer)\b'
  selection_suspicious_parent:
    EventID: 1
    ParentImage|re:
      - '(?i)\\(explorer|msedge|chrome|firefox|iexplore|powershell|cmd)\.exe$'
  condition: selection_system_binaries_created and selection_expected_system_paths and (selection_user_writable_locations or selection_copy_tools_process or selection_suspicious_parent)
fields:
  - timestamp
  - EventID
  - ComputerName
  - SubjectUserName
  - TargetFilename
  - Image
  - ParentImage
  - CommandLine
  - ProcessId
falsepositives:
  - Legitimate software installers, developer tools, or packaging processes that stage system-named binaries in non-system locations (whitelist known build servers and deployment tools).
  - Forensic or backup operations that intentionally copy system files for analysis or imaging.
level: high
tags:
  - attack.defense_evasion
  - attack.persistence
  - attack.t1036
  - detection.windows.sysmon
notes: |
  - Tuning: add allowlists for known deployment/CI hosts, signed installers, and administrative accounts; consider requiring additional context (e.g., unsigned binary, unusual parent process, or network C2 activity) to reduce noise.
  - Investigation: collect the created file (preserve), compute hashes, check digital signature, examine parent/child process tree, review command line and source path, search for similar artifacts across the estate, and check for subsequent persistence or execution.
  - Response: isolate affected host if malicious, remove unauthorized copies, block source URLs/IPs, revoke compromised credentials, and perform a broader hunt for other masquerading artifacts.

# Arquivo: C.yml
title: BazaLoader Masquerading - PDF File Renamed to DLL and Executed via rundll32
id: 8c3f1e72-5b04-4d9a-a618-3e7f2d094c5a
status: experimental
description: |
    Detects the BazaLoader delivery technique first reported by @ffforward
    (January 2022) and codified in Atomic Red Team T1036 Atomic Test #2.

    The technique works as follows:

      Step 1 — A phishing email delivers a ZIP archive containing two files:
                 README.cmd   — a batch script masquerading as documentation
                 <name>.pdf   — the BazaLoader DLL with a .pdf extension
                               (passes mail gateway inspection since .pdf is benign)

      Step 2 — The victim extracts the ZIP and opens README.cmd, which executes
                two key commands:
                  a) ren <name>.pdf <name>.dll   (rename the disguised payload)
                  b) rundll32 <name>.dll,<export> (execute the now-renamed DLL)

      Step 3 — BazaLoader initialises, beacons to C2, and fetches Cobalt Strike
                or a second-stage ransomware payload.

    The detection has two complementary branches:

    BRANCH A (file_rename): A file with .pdf extension is renamed to .dll. This
    combination — not a .pdf being opened, not a .dll being written fresh, but
    specifically a .pdf renamed to .dll — has no known legitimate use case. The
    rename event is the earliest possible detection point, before any code runs.

    BRANCH B (process_creation): rundll32.exe is executed with a command line
    that references a DLL in a user-writable directory (Downloads, Temp, AppData,
    Desktop, or a path matching %USERPROFILE%) by an ancestor cmd.exe process.
    This catches the execution even if the rename event is missed (e.g., on hosts
    without file-rename telemetry).

    Both branches are high-confidence in isolation; together they form a kill
    chain correlation that eliminates virtually all false positives.

    Malware family context:
      BazaLoader (aka BazarLoader) was developed by the TrickBot group and widely
      used from 2020–2022 as an initial-access loader delivering Cobalt Strike,
      Ryuk, Conti, and other ransomware families. This specific delivery variant
      abuses the .pdf extension to bypass mail filters and endpoint AV that rely
      on extension-based inspection without reading file magic bytes.

    References:
      - https://twitter.com/ffforward/status/1481672378639912960
      - https://github.com/redcanaryco/atomic-red-team/blob/f339e7da7d05f6057fdfcdd3742bfcf365fee2a9/atomics/T1036/T1036.md#atomic-test-2---malware-masquerading-and-execution-from-zip-file
      - https://attack.mitre.org/techniques/T1036/   (Masquerading)
      - https://attack.mitre.org/techniques/T1218/011/ (Signed Binary Proxy: Rundll32)

author: Claude (based on @ffforward reporting and Red Canary Atomic Red Team)
date: 2026-06-06
modified: 2026-06-06

    - attack.t1036                # Masquerading
    - attack.t1036.008            # Masquerading: Masquerade File Type

title: BazaLoader - PDF Renamed to DLL (File Rename Indicator)
id: 8c3f1e72-5b04-4d9a-a618-3e7f2d094c5a
status: experimental
description: >
    Branch A — file rename event: a file with .pdf extension is renamed to .dll.
    This has no legitimate use case and is the earliest detection point for the
    BazaLoader PDF-masquerade delivery technique (@ffforward, Jan 2022).
    Correlate with rule 1d94b7a3-... (rundll32 execution from user dir) within 30s
    on the same host for confirmed kill-chain match.
tags:
    - attack.defense-evasion
    - attack.t1036.008
logsource:
    category: file_rename          # Sysmon EID 11 + rename semantics; MDE FileRenamed
    product: windows
detection:
    selection:
        # Old name ends with .pdf, new name ends with .dll on the same file object.
        # Field names vary by EDR — adjust as needed:
        #   Sysmon:  TargetFilename (new), PreviousTargetFilename (old name before rename)
        #   MDE:     FolderPath + FileName (new), PreviousFileName (old)
        #   Falcon:  TargetFileName, OldFileName
        PreviousTargetFilename|endswith: '.pdf'
        TargetFilename|endswith: '.dll'
    filter_system_paths:
        # Exclude renames in system-managed directories where legitimate
        # software update chains (very rarely) swap versioned files.
        TargetFilename|startswith:
            - 'C:\Windows\'
            - 'C:\Program Files\'
            - 'C:\Program Files (x86)\'
    condition: selection and not filter_system_paths
falsepositives:
    - Intentional developer file manipulation (local dev environment) — extremely rare
    - No known legitimate software performs this rename in user-writable directories
level: high

title: BazaLoader - rundll32 Executing DLL From User-Writable Directory via cmd.exe
id: 1d94b7a3-8e52-4f0b-c729-5a3b1e806d8f
status: experimental
description: >
    Branch B — process creation: rundll32.exe executing a DLL from a user-writable
    path (Downloads, Temp, AppData, Desktop) where the parent or grandparent process
    is cmd.exe. This matches the README.cmd → rundll32 execution step of the
    BazaLoader PDF-masquerade delivery chain. High-confidence standalone; correlate
    with Branch A (PDF→DLL rename) for kill-chain confirmation.
tags:
    - attack.execution
    - attack.t1218.011
    - attack.defense-evasion
    - attack.t1036
logsource:
    category: process_creation
    product: windows
detection:
    selection_rundll32:
        Image|endswith: '\rundll32.exe'
        # DLL executed from a user-writable path — not from System32/SysWOW64
        CommandLine|contains:
            - '\Downloads\'
            - '\AppData\'
            - '\Temp\'
            - '\Desktop\'
            - '\Users\'
        CommandLine|endswith: '.dll'

    selection_cmd_parent:
        # The .cmd script spawns rundll32 directly or via a child cmd.exe
        ParentImage|endswith: '\cmd.exe'

    selection_cmd_grandparent:
        # Alternative: grandparent is cmd.exe (cmd → cmd → rundll32)
        # Use if your EDR provides ParentOfParentImage
        ParentImage|endswith: '\cmd.exe'

    # Secondary signal: the CommandLine contains the classic ren .pdf .dll pattern
    # This catches the rename command itself as it appears in cmd.exe's CommandLine
    # when the parent cmd.exe process is logged (Sysmon EID 1 for cmd spawning ren).
    selection_rename_cmdline:
        Image|endswith: '\cmd.exe'
        CommandLine|contains|all:
            - '.pdf'
            - '.dll'
            - 'ren'         # ren or rename builtin

    filter_legitimate_rundll32:
        # Known-good rundll32 invocations from user paths (tune to your environment)
        CommandLine|contains:
            - 'printui.dll'
            - 'shell32.dll'
            - 'dfshim.dll'      # ClickOnce
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\svchost.exe'

    condition: >
        (
          ( selection_rundll32 and selection_cmd_parent )
          or selection_rename_cmdline
        )
        and not filter_legitimate_rundll32

falsepositives:
    - Custom in-house deployment scripts that invoke rundll32 from user directories
      (address by extending filter_legitimate_rundll32 with known script hashes)
    - Developer workflows running DLLs from local build output directories
level: high

# ── Analyst triage workflow ────────────────────────────────────────────────────
# 1. Is there a corresponding file_rename event (Branch A) on the same host
#    within 30 seconds? If yes, confirmed BazaLoader pattern — escalate.
# 2. Check the directory for a ZIP file or .cmd file extracted recently
#    (file_create events with .zip / .cmd extension in the same parent directory).
# 3. Examine the DLL's PE header: BazaLoader DLLs typically have a very recent
#    compile timestamp and are 100–300 KB. Check VirusTotal via hash.
# 4. Check network connections from rundll32 or its children in the 60s after
#    execution — BazaLoader beacons to HTTPS C2 shortly after init.
# 5. Look for a subsequent mshta.exe, powershell.exe, or cobalt-strike-watermark
#    beacon process as a second-stage indicator.
#
# Atomic Test cleanup command for lab validation:
#   remove-item "$env:allusersprofile\<name>.dll" -force -erroraction silentlycontinue

            - '\calc.exe'
            - '\wscript.exe'

title: Non-DLL Extension File Renamed With DLL Extension
id: bbfd974c-248e-4435-8de6-1e938c79c5c1
status: test
description: |
    Detects rename operations of files with non-DLL extensions to files with a DLL extension. This is often performed by malware in order to avoid initial detections based on extensions.
references:
    - https://twitter.com/ffforward/status/1481672378639912960
    - https://github.com/redcanaryco/atomic-red-team/blob/f339e7da7d05f6057fdfcdd3742bfcf365fee2a9/atomics/T1036/T1036.md#atomic-test-1---system-file-copied-to-unusual-location
author: frack113
date: 2022-02-19
modified: 2023-11-11
tags:
    - attack.stealth
    - attack.t1036.008
    - detection.threat-hunting
logsource:
    product: windows
    category: file_rename
    definition: 'Requirements: Microsoft-Windows-Kernel-File Provider with at least the KERNEL_FILE_KEYWORD_RENAME_SETLINK_PATH keyword'
detection:
    selection:
        TargetFilename|endswith: '.dll'
    filter_main_dll:
        # Note: To avoid file renames
        SourceFilename|endswith: '.dll'
    filter_main_installers:
        SourceFilename|endswith: '.tmp'
    filter_main_empty_source:
        SourceFilename: ''
    filter_main_null_source:
        SourceFilename: null
    filter_main_tiworker:
        Image|contains: ':\Windows\WinSxS\'
        Image|endswith: '\TiWorker.exe'
    filter_main_upgrade:
        - Image|endswith: ':\Windows\System32\wuauclt.exe'
        - TargetFilename|contains: ':\$WINDOWS.~BT\Sources\'
    filter_main_generic:
        Image|contains:
            - ':\Program Files (x86)\'
            - ':\Program Files\'
    filter_optional_squirrel:
        SourceFilename|contains: '\SquirrelTemp\temp'
    condition: selection and not 1 of filter_main_* and not 1 of filter_optional_*
falsepositives:
    - Likely from installers and temporary locations
level: medium
