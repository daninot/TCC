# Arquivo: A.yml
title: JVM Application Path Traversal Attempt via File Exception in Error Log
id: 7c4a1e8f-3b2d-4f6c-a9e1-5d8b3c7f2a14
status: experimental
description: >
  Detects co-occurrence of a Java file-access exception class and a path
  traversal sequence in the same JVM application error log entry. When
  user-controlled input is passed unsanitised into a file-read operation,
  the JVM emits a FileNotFoundException or NoSuchFileException whose message
  includes the attacker-supplied path. Adversaries exploit local file read
  vulnerabilities to exfiltrate sensitive files such as /etc/passwd,
  application configuration files, private keys, or cloud instance metadata.
  The path traversal pattern ../ in the exception message is the canonical
  indicator that a relative path has been injected to escape the intended
  directory. Requiring both the exception class name and the traversal
  pattern to appear in the same log line significantly reduces noise from
  benign file-not-found conditions triggered by missing configuration or
  resource files. Requires application error logs to be collected at
  LOG_LEVEL ERROR or above and forwarded to the SIEM. Environments that
  log below the ERROR threshold or suppress exception stack traces in
  production will not surface these events.
references:
  - https://www.wix.engineering/post/threat-and-vulnerability-hunting-with-application-server-error-logs
author: Senior Threat Detection Engineer
date: 2026-05-25
tags:
  - attack.initial_access
  - attack.credential_access
  - attack.t1190
  - attack.t1083
logsource:
  product: jvm
  category: application
  definition: >
    Requirements: application error logging must be enabled at LOG_LEVEL
    ERROR or above and exception messages must be included in the log
    output. JVM applications that suppress exception detail in production
    logs or redirect ERROR output to a separate sink not ingested by the
    SIEM will not surface these events.
detection:
  keywords|all:
    - 'FileNotFoundException'
    - '../'
  condition: keywords
falsepositives:
  - Misconfigured application deployments where a relative path containing
    .. is legitimately used to reference a file outside the working
    directory as part of an approved directory layout, causing benign
    FileNotFoundException entries that match the traversal pattern.
  - Integration test suites that exercise error-handling code paths by
    supplying invalid or nonexistent file paths containing traversal
    sequences in a non-production environment.
level: medium

description: Detects local file read vulnerability exploitation attempts in JVM-based applications via error logs showing file-not-found exceptions containing path traversal sequences.
references:
    - https://www.wix.engineering/post/threat-and-vulnerability-hunting-with-application-server-error-logs
author: Senior Threat Detection Engineer
date: 2026-06-03
logsource:
    product: jvm
    category: application
detection:
    # Documentation: Requires LOG_LEVEL ERROR or above to capture file errors
    selection:
        message|all:
            # Java file exception classes
            - 'FileNotFoundException'
            - 'NoSuchFileException'
            - 'IOException'
            # Path traversal patterns
            - '../'
            - '..\\'
            - '..%2f'
            - '..%5c'
    condition: selection

    - Legitimate application errors involving filenames that contain '../' as part of a valid path (rare).
    - Scanning or backup tools generating file-not-found errors.
level: medium

# Arquivo: E.yml
title: JVM Application Error Logs Indicating Path Traversal File Read Exploitation
id: 8d2f1a4b-3c6e-4f9a-b2d7-1e3f5c6a7b8e
status: experimental
description: Detects unstructured JVM application error logs at ERROR level or above where a Java file-related exception co-occurs with path traversal sequences (e.g., ../ or ..\), indicating potential exploitation attempts to read local files via path traversal.
author: Senior Threat Detection Engineer
date: 2026/06/03
references:
  - [https://www.wix.engineering/post/threat-and-vulnerability-hunting-with-application-server-error-logs](https://www.wix.engineering/post/threat-and-vulnerability-hunting-with-application-server-error-logs)
tags:
  - attack.exploitation
  - attack.initial_access
  - vulnerability
  - detection
logsource:
  product: jvm
  category: application
  description: Application error logs from JVM-based applications. Application error logging must be enabled and capture full unstructured log messages at ERROR level or above.
detection:
  selection_loglevel:
    LogLevel|in:
      - 'ERROR'
      - 'ERR'
      - 'FATAL'
      - 'SEVERE'
  selection_pattern_1:
    Message|contains|all:
      - 'FileNotFoundException'
      - '../'
  selection_pattern_2:
    Message|contains|all:
      - 'FileNotFoundException'
      - '..\\'
  selection_pattern_3:
    Message|contains|all:
      - 'NoSuchFileException'
      - '../'
  selection_pattern_4:
    Message|contains|all:
      - 'NoSuchFileException'
      - '..\\'
  condition: selection_loglevel and (selection_pattern_1 or selection_pattern_2 or selection_pattern_3 or selection_pattern_4)
falsepositives:
  - Legitimate application errors where user-supplied input includes relative paths for valid reasons (file upload handlers, user file references).
  - Developers or QA triggering path traversal in test environments.
level: high
