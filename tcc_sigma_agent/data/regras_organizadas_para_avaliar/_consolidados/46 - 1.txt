# Arquivo: A.yml
title: Remote Service Installation from Unusual Location
id: 2026-06-08-remote-service-installation-0001
status: experimental
description: Detects creation or installation of Windows services where the service binary is located in user-writable or non-standard system locations, or where service installation is performed by uncommon tools or parent processes. Attackers often install services to achieve persistence by placing service executables in Downloads, Temp, AppData, or network shares and using sc.exe, powershell, wmic, or service wrappers (nssm/srvany). Correlate service install events with process creation and file writes to raise confidence.
author: Detection Engineer
date: 2026-06-08
references:
  - https://threathunterplaybook.com/hunts/windows/190815-RemoteServiceInstallation/notebook.html
logsource:
  product: windows
  service: security,sysmon
  category: process_creation,service_installation,file_event
detection:
  selection_service_install_event:
    EventID: 7045
    # Windows Security log: A service was installed
  selection_service_image_path_unusual:
    EventID: 7045
    ServiceFileName|re:
      - '(?i)\\Users\

\[^\\]

+\\'
      - '(?i)\\AppData\\Local\\Temp\\'
      - '(?i)\\AppData\\Roaming\\'
      - '(?i)\\Users\\Public\\'
      - '(?i)\\.*\\Downloads\\'
      - '(?i)\\\\Temp\\\\'
      - '(?i)^[a-z]:\\.*\

\[^\\]

+\

\[^\\]

+\\.(exe|dll)$'
  selection_service_image_network:
    EventID: 7045
    ServiceFileName|re:
      - '(?i)^(\\\\\\\\|https?:\/\/|file:\/\/)'
  selection_service_installer_tools:
    EventID: 1
    Image|re:
      - '(?i)\\sc\.exe$'
      - '(?i)\\wmic\.exe$'
      - '(?i)\\powershell(\.exe)?$'
      - '(?i)\\pwsh(\.exe)?$'
      - '(?i)\\regsvr32\.exe$'
      - '(?i)\\nssm\.exe$'
      - '(?i)\\srvany\.exe$'
    CommandLine|re:
      - '(?i)\bcreate\b|\bcreate service\b|\bcreateobject\b|\bNew-Service\b|\bInstall-Service\b|\bsc\s+create\b'
  selection_service_installer_parent_unusual:
    EventID: 1
    ParentImage|re:
      - '(?i)\\(msedge|chrome|firefox|iexplore|outlook|winword|excel|powerpnt)\.exe$'
  selection_file_write_service_binary:
    EventID: 11
    TargetFilename|re:
      - '(?i)\\Users\

\[^\\]

+\\.*\.(exe|dll|ps1|bat|cmd)$'
      - '(?i)\\AppData\\Local\\Temp\\.*\.(exe|dll|ps1|bat|cmd)$'
  selection_unsigned_service_binary:
    EventID: 11
    TargetFilename|re:
      - '(?i)\.(exe|dll)$'
    Signed: "false"
  selection_rapid_service_install_after_write:
    # Correlate: file write followed by service install within short timeframe
    correlation:
      - when: selection_file_write_service_binary
      - then: selection_service_install_event
      - within: "2m"
  condition: |
    (selection_service_install_event and (selection_service_image_path_unusual or selection_service_image_network))
    or (selection_service_installer_tools and (selection_service_installer_parent_unusual or selection_service_image_path_unusual))
    or selection_rapid_service_install_after_write
fields:
  - timestamp
  - EventID
  - ComputerName
  - SubjectUserName
  - ServiceName
  - ServiceFileName
  - Image
  - ParentImage
  - CommandLine
  - TargetFilename
  - Signed
  - ProcessId
falsepositives:
  - Legitimate installers, developer tools, or enterprise deployment systems that stage or install services in non-standard locations (whitelist known deployment servers and automation accounts).
  - Portable or self-contained applications intentionally installed by users to non-system paths.
level: high
tags:
  - attack.persistence
  - attack.t1543
  - attack.t1543.003
  - detection.windows
  - hunting.remote_service_installation
notes: |
  - Tuning: whitelist known CI/CD, deployment, and backup hosts; restrict detection to external-facing or user endpoints and to service installs by non-admin or unusual parent processes.
  - Investigation: collect the service binary, compute hashes, check digital signature, capture full process tree and command lines for the installer, review network connections from the host, and search for other hosts with the same service binary or installer command lines.
  - Response: if malicious, stop and disable the service, isolate the host, remove the binary, rotate credentials if present, and perform a broader hunt for related persistence mechanisms.

# Arquivo: B.yml
title: Windows - Remote Service Installation via Network Logon Session (T1543.003)
id: 7f3a9e42-1c85-4d67-b092-5e8d4c9f2b14
status: test
description: |
    Detects new Windows service installations likely performed from a remote host,
    as documented in the Threat Hunter Playbook (190815-RemoteServiceInstallation)
    by Roberto Rodriguez (@Cyb3rWard0g).

    The playbook's Analytic I correlates two Windows Security events:
      - EventID 4697: A new service was installed on the system.
      - EventID 4624 (LogonType=3): Network logon session.

    The correlation pivot is SubjectLogonId (4697) == TargetLogonId (4624 Type 3).
    When a service is installed within a network logon session, it means the
    installation was initiated from a remote endpoint — the defining artefact of
    lateral movement via service creation (PsExec, Impacket psexec.py, Empire,
    Cobalt Strike jump psexec).

    This Sigma rule targets EventID 4697 with two complementary detection tiers:

    1. selection_suspicious_path (HIGH confidence): ServiceFileName in Temp
       directories, UNC admin share paths, or Windows root with short random
       filenames — the canonical drop locations for remote execution tools.

    2. selection_any_install (MEDIUM, broader): Any service installation by a
       non-machine account. Noisy alone but essential for complete coverage;
       correlate with EventID 4624 LogonType=3 on the same host within a 15-minute
       window using your SIEM's correlation engine for definitive attribution.

    Dataset reference: empire_psexec_dcerpc_tcp_svcctl (Security Datasets OTRF)
references:
    - https://threathunterplaybook.com/hunts/windows/190815-RemoteServiceInstallation/notebook.html
    - https://securitydatasets.com/notebooks/atomic/windows/lateral_movement/SDWIN-190518210652.html
    - https://attack.mitre.org/techniques/T1543/003/
    - https://attack.mitre.org/techniques/T1021/002/
author: Security Team
date: 2026-06-07
tags:
    - attack.lateral_movement
    - attack.t1021.002   # Remote Services: SMB/Windows Admin Shares (PsExec vector)
    - attack.persistence
    - attack.privilege_escalation
    - attack.t1543.003   # Create or Modify System Process: Windows Service
logsource:
    product: windows
    service: security
detection:
    selection_service_install:
        # Base: any new service installation event
        EventID: 4697
    selection_suspicious_path:
        # Tier 1 (HIGH) — ServiceFileName in locations used by remote execution tools
        ServiceFileName|contains:
            - '\Temp\'                # Windows/User Temp staging areas
            - '\tmp\'
            - 'ADMIN$'               # PsExec / Impacket admin share path
            - '\C$\'                 # Direct UNC admin share access
            - '\IPC$\'
    selection_windows_root:
        # Tier 1b — service executable directly under C:\Windows\ (not System32)
        # PsExec drops PSEXESVC.exe here; Impacket drops random-named executables
        ServiceFileName|re: '^[Cc]:\\[Ww][Ii][Nn][Dd][Oo][Ww][Ss]\\[^\\]+\.(exe|dll|bat|cmd|ps1)$'
    filter_machine_accounts:
        # Machine accounts ($) legitimately install services during OS operations
        SubjectUserName|endswith: '$'
    filter_known_windows_paths:
        # Suppress well-known legitimate service binaries in Windows root
        ServiceFileName|contains:
            - '\Windows\System32\'
            - '\Windows\SysWOW64\'
            - '\Windows\servicing\'
            - '\Windows\WinSxS\'
    condition: >
        selection_service_install
        and (selection_suspicious_path or selection_windows_root)
        and not filter_machine_accounts
        and not filter_known_windows_paths
fields:
    - SubjectUserName
    - SubjectLogonId
    - ServiceName
    - ServiceFileName
    - ServiceType
    - ServiceStartType
    - ServiceAccount
falsepositives:
    - Legitimate remote management software (SCCM, Ansible, Puppet) deploying
      services via administrative shares — add known management server IPs/accounts
      to filter_machine_accounts or a dedicated filter block
    - System backup agents that install services during backup operations
    - Security software temporarily dropping components in Windows root
level: high

# Arquivo: C.yml
title: Suspicious Remote Service Installation Path
id: 9c1488cb-04e3-40fa-bfce-15ce92a83e71
status: experimental
description: |
  Detects the installation of a new Windows service (Event ID 7045) where the image path points to administrative shares (ADMIN$, C$), temporary user directories, or leverages living-off-the-land command interpreters (cmd.exe, powershell.exe). 
  This behavior is highly indicative of lateral movement, remote code execution via PsExec-like tools, or malicious persistence mechanisms as outlined in the Threat Hunter Playbook.
author: Gemini
date: 2026/06/08
references:
    - https://threathunterplaybook.com/hunts/windows/190815-RemoteServiceInstallation/notebook.html
    - https://attack.mitre.org/techniques/T1569/002/
tags:
    - attack.lateral_movement
    - attack.persistence
    - attack.privilege_escalation
    - attack.t1569.002
    - attack.t1543.003
logsource:
    product: windows
    service: system
detection:
    selection:
        EventID: 7045
        ImagePath|contains:
            - '\ADMIN$\'
            - '\C$\'
            - '\Temp\'
            - 'cmd.exe /c'
            - 'powershell.exe'
            - 'pwsh.exe'
            - '%COMSPEC%'
            - 'rundll32.exe'
    condition: selection
falsepositives:
    - IT administrators legitimately using Sysinternals PsExec to deploy software or troubleshoot systems (which will flag on the \ADMIN$\ path and PSEXESVC).
    - Enterprise vulnerability scanners (like Nessus or Qualys) performing authenticated credentialed checks.
level: high

# Arquivo: D.yml
title: Remote Service Installation via Network Logon
id: 4a3a2b96-d7fc-4cb9-80e4-4a545fe95f46
status: test
description: |
    Detects when a new service is installed (EventID 4697) following a network logon
    (EventID 4624, LogonType=3). This pattern is indicative of remote lateral movement
    or persistence, as documented in the Threat Hunter Playbook.
references:
    - https://threathunterplaybook.com/hunts/windows/190815-RemoteServiceInstallation/notebook.html
author: Jai Minton, oscd.community
date: 2020/10/05
tags:
    - attack.lateral_movement
    - attack.persistence
    - attack.execution
    - attack.t1543.003
logsource:
    product: windows
    service: security
detection:
    # First event: Network logon (EventID 4624, LogonType=3)
    event1:
        EventID: 4624
        Logon_Type: 3
    # Second event: Service installation (EventID 4697)
    event2:
        EventID: 4697
    timeframe: 30s
    condition: (event1 and not filter1) and event2
    filter1:
        Source_Network_Address:
            - '::1'
            - '127.0.0.1'
falsepositives:
    - Legitimate remote administrative actions (e.g., IT support scripts, configuration management).
    - Network logons from localhost or IPv6 loopback.
level: high

description: Detects alternate PowerShell hosts potentially bypassing detections looking for powershell.exe
references:
    - https://threathunterplaybook.com/hunts/windows/190815-RemoteServiceInstallation/notebook.html
author: Roberto Rodriguez @Cyb3rWard0g
date: 2019-08-11
modified: 2025-10-22
tags:
    - attack.execution
    - attack.t1059.001
    - detection.threat-hunting
logsource:
    product: windows
    category: ps_classic_start
detection:
    selection:
        Data|contains: 'HostApplication='
    # Note: Powershell Logging Data is localized. Meaning that "HostApplication" field will be translated to a different field on a non english layout. This rule doesn't take this into account due to the sheer ammount of possibilities. It's up to the user to add these cases.
    filter_main_ps:
        Data|contains:
            - 'HostApplication=?:/Windows/System32/WindowsPowerShell/v1.0/powershell' # In some cases powershell was invoked with inverted slashes
            - 'HostApplication=?:/Windows/SysWOW64/WindowsPowerShell/v1.0/powershell' # In some cases powershell was invoked with inverted slashes
            - 'HostApplication=?:\Windows\System32\sdiagnhost.exe'
            - 'HostApplication=?:\Windows\System32\WindowsPowerShell\v1.0\powershell'
            - 'HostApplication=?:\Windows\SysWOW64\sdiagnhost.exe'
            - 'HostApplication=?:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell'
            - 'HostApplication=powershell'
    filter_optional_citrix:
        Data|contains: 'Citrix\ConfigSync\ConfigSync.ps1'
    filter_optional_hexnode:
        Data|contains: 'HostApplication=C:\Hexnode\Hexnode Agent\Current\HexnodeAgent.exe'
    condition: selection and not 1 of filter_main_* and not 1 of filter_optional_*
falsepositives:
    - Programs using PowerShell directly without invocation of a dedicated interpreter
    - MSP Detection Searcher
    - Citrix ConfigSync.ps1
level: medium
