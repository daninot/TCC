# Arquivo: B.yml
title: Potential SQL Injection Probing via Database Error Messages
id: 7c8d9e0f-1a2b-3c4d-5e6f-7a8b9c0d1e2f
status: experimental
description: Detects SQL error messages in application logs that may indicate attackers probing for SQL injection vulnerabilities by triggering syntax errors in Oracle, MySQL, SQL Server, or SQLite backends.
references:
    - http://www.sqlinjection.net/errors
author: Senior Threat Detection Engineer
date: 2026-06-02
logsource:
    product: sql
    category: application
detection:
    selection:
        # Level documentation: requires LOG_LEVEL ERROR or above to capture SQL errors
        level: ERROR
        message|contains:
            # Oracle
            - 'ORA-'
            # MySQL
            - 'You have an error in your SQL syntax'
            # SQL Server
            - 'Unclosed quotation mark after the character string'
            # SQLite
            - 'SQLiteException'
    condition: selection
falsepositives:
    - Legitimate application errors due to malformed user input or bugs.
    - Maintenance scripts or internal testing.
level: medium
tags:
    - attack.initial_access
    - attack.t1190
    - attack.t1133

# Arquivo: D.yml
title: SQL Injection Probe Indicated by Database Engine Syntax Error
id: 3a8f1d2b-7c4e-4b9f-a5d3-6e2c1b8f4a07
status: experimental
description: >
  Detects characteristic database engine error messages in SQL application
  logs that are emitted when attacker-supplied input causes the database to
  fail while parsing or executing a malformed SQL statement. Each keyword
  represents the single most unambiguous injection-triggered syntax error for
  one of the four most commonly targeted backend engines: MySQL, Microsoft
  SQL Server, Oracle, and SQLite. Attackers deliberately induce these errors
  during the reconnaissance and fingerprinting phases of a SQL injection
  attack to confirm that unsanitised input reaches the query layer and to
  identify the backend engine before selecting an engine-specific exploitation
  payload. A burst of these messages over a short timeframe is a strong
  indicator of automated injection tooling. Requires application error logs
  to be collected at LOG_LEVEL ERROR or above and forwarded to the SIEM;
  logs captured at WARNING or DEBUG level are out of scope and will not
  surface these events.
references:
  - http://www.sqlinjection.net/errors
author: Senior Threat Detection Engineer
date: 2026-05-25
tags:
  - attack.initial_access
  - attack.t1190
logsource:
  product: sql
  category: application
  definition: >
    Requirements: application error logging must be enabled at LOG_LEVEL
    ERROR or above on the target database service and forwarded to the SIEM.
    Environments with error logging disabled or set below the ERROR threshold
    will not surface the events this rule depends on.
detection:
  keywords:
    - 'You have an error in your SQL syntax'
    - 'Unclosed quotation mark after the character string'
    - 'ORA-'
    - 'SQLite error'
  condition: keywords
falsepositives:
  - Genuine application bugs or ORM misconfigurations that produce malformed
    queries in development or staging environments, triggering the same error
    signatures without any malicious intent.
  - Database migration or schema management tooling that produces transient
    syntax errors when applying patches against a mismatched engine version.
  - Automated integration-test suites that intentionally exercise
    error-handling paths and generate SQL errors as part of regression
    testing in non-production environments.
level: medium

# Arquivo original: app_sqlinjection_errors.yml
title: Suspicious SQL Error Messages
id: 8a670c6d-7189-4b1c-8017-a417ca84a086
status: test
description: Detects SQL error messages that indicate probing for an injection attack
references:
    - http://www.sqlinjection.net/errors
author: Bjoern Kimminich
date: 2017-11-27
modified: 2023-02-12
tags:
    - attack.initial-access
    - attack.t1190
logsource:
    category: application
    product: sql
    definition: 'Requirements: application error logs must be collected (with LOG_LEVEL ERROR and above)'
detection:
    keywords:
        # Oracle
        - quoted string not properly terminated
        # MySQL
        - You have an error in your SQL syntax
        # SQL Server
        - Unclosed quotation mark
        # SQLite
        - 'near "*": syntax error'
        - SELECTs to the left and right of UNION do not have the same number of result columns
    condition: keywords
falsepositives:
    - A syntax error in MySQL also occurs in non-dynamic (safe) queries if there is an empty in() clause, that may often be the case.
level: high
