# Arquivo: A.yml
title: Creation or Modification of doas.conf on Linux
id: 1c9f4e2b-7a6d-4b2f-9c1e-0b2a3d4e5f7b
status: experimental
description: Detects creation or modification of the doas configuration file (/etc/doas.conf). Unexpected writes or edits to this file by non-root users, unusual editors, or via suspicious parent processes may indicate privilege escalation attempts or persistence on Linux systems using doas.
author: Daniela
date: 2026-06-04
references:
  - https://research.splunk.com/endpoint/linux_doas_conf_file_creation/
  - https://www.makeuseof.com/how-to-install-and-use-doas/
logsource:
  product: linux
  service: auditd
  category: file_event
detection:
  selection_audit_write:
    EventType: "SYSCALL"
    Syscall|in:
      - "open"
      - "openat"
      - "creat"
      - "truncate"
      - "write"
    Success: "yes"
    Path|endswith: 
      - "/etc/doas.conf"
  selection_audit_chmod:
    EventType: "SYSCALL"
    Syscall|in:
      - "chmod"
      - "fchmod"
      - "fchmodat"
    Success: "yes"
    Path|endswith:
      - "/etc/doas.conf"
  selection_editor_write:
    EventType: "PROCESS"
    ProcessName|in:
      - "vi"
      - "vim"
      - "nano"
      - "ed"
      - "sed"
      - "tee"
      - "cp"
      - "mv"
    CommandLine|contains:
      - "/etc/doas.conf"
  selection_non_root_actor:
    User|not_in:
      - "root"
      - "uid=0"
  selection_suspicious_parent:
    ParentProcess|contains:
      - "wget"
      - "curl"
      - "python"
      - "perl"
      - "bash"
      - "sh"
      - "nc"
  condition: (selection_audit_write or selection_audit_chmod or selection_editor_write) and (selection_non_root_actor or selection_suspicious_parent)
fields:
  - timestamp
  - Hostname
  - User
  - UID
  - GID
  - Path
  - Syscall
  - ProcessName
  - ParentProcess
  - CommandLine
falsepositives:
  - Legitimate administrative edits by root or authorized operators (whitelist known admin accounts)
  - Automated configuration management tools (Ansible, Puppet, Chef) that intentionally manage /etc/doas.conf
level: high
tags:
  - attack.privilege_escalation
  - attack.persistence
  - linux
  - configuration
  - detection.audit
notes: |
  - Tune by whitelisting known automation service accounts and management hosts.
  - Recommended response: collect the full audit record, capture the editing process command line and parent process tree, verify the integrity and contents of /etc/doas.conf, and investigate the actor and source host for lateral movement or other suspicious activity.

# Arquivo: C.yml
title: Linux - doas Privilege Escalation Config File Created (T1548.003)
id: 6f8a2e41-3c75-4d90-b012-5e7d9c4b8f23
status: test
description: |
    Detects the creation of a doas configuration file on Linux systems, as documented
    by the Splunk Threat Research team (linux_doas_conf_file_creation, T1548.003).

    doas is an OpenBSD-origin privilege escalation utility (minimalistic sudo alternative)
    ported to Linux, configured via /etc/doas.conf. An attacker with root access can
    install doas and configure it with "permit nopass" to create a persistent, passwordless
    backdoor for any local user account, surviving password resets and independent of
    the sudoers configuration which is more commonly monitored.

    Malicious doas.conf entries (from makeuseof.com doas syntax documentation):
      "permit nopass username as root"         — passwordless root (backdoor)
      "permit nopass username cmd bash as root" — direct root shell without password

    Unlike /etc/sudoers, /etc/doas.conf is not monitored by most default SIEM and
    EDR configurations, making doas a stealthier persistence mechanism than sudo
    modifications. doas is NOT present by default in most enterprise Linux distributions
    (Debian stable, RHEL, CentOS, Amazon Linux, Ubuntu LTS). Any creation of
    /etc/doas.conf in environments where doas is not deliberately deployed warrants
    immediate investigation.
references:
    - https://research.splunk.com/endpoint/linux_doas_conf_file_creation/
    - https://www.makeuseof.com/how-to-install-and-use-doas/
    - https://attack.mitre.org/techniques/T1548/003/
    - https://github.com/slicer69/doas
author: Security Team
date: 2026-05-25
tags:
    - attack.privilege_escalation
    - attack.t1548.003   # Abuse Elevation Control Mechanism: Sudo and Sudo Caching
    - attack.persistence
    - attack.t1098       # Account Manipulation (configuring user for persistent escalation)
logsource:
    category: file_create
    product: linux
    definition: |
        Requires Sysmon for Linux (EventID 11 - FileCreate) or auditd configured
        with a watch rule: -w /etc -p wa -k doas_conf_creation
        Alternatively, FIM tools monitoring /etc/doas.conf changes will generate
        compatible file_create events.
detection:
    selection_doas_conf:
        # Primary: /etc/doas.conf — the canonical doas configuration path
        # Malicious entries use "permit nopass" to grant passwordless root access
        TargetFilename: '/etc/doas.conf'
    selection_doas_conf_alt:
        # Alternative paths used by some distributions or custom installations
        TargetFilename|endswith: '/doas.conf'
    selection_doas_binary:
        # doas binary installation — precursor signal; rarely present on enterprise Linux
        # Packages: 'doas' (Debian/Ubuntu) / 'opendoas' (Arch/Fedora)
        TargetFilename|contains:
            - '/usr/local/bin/doas'
            - '/usr/bin/doas'
            - '/usr/local/sbin/doas'
    filter_package_managers:
        # Package managers legitimately create these files when doas is explicitly installed
        # Populate below ONLY if doas is an authorized tool in your environment:
        # Image|endswith:
        #     - '/dpkg'
        #     - '/rpm'
        #     - '/apt'
        #     - '/dnf'
        #     - '/pacman'
        Image: null   # placeholder — populate only if doas is authorized
    condition: (1 of selection_*) and not filter_package_managers
fields:
    - Image
    - TargetFilename
    - User
    - ProcessId
    - ParentImage
falsepositives:
    - Authorized installation of doas via package manager in environments that
      intentionally use doas as a sudo alternative (use filter_package_managers)
    - Configuration management tools (Ansible, Puppet, Chef) deploying doas configs
    - System administrators intentionally replacing sudo with doas on BSDs/Linux
    - Developer workstations running OpenBSD-based containers or VMs with doas
level: medium
