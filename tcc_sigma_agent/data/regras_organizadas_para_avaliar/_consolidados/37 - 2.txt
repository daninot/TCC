# Arquivo: B.yml
title: NodeJS Child Process Execution Error Indicating RCE Attempt
id: 8f3b1d4e-7c2a-4f9b-a5e3-2d6c1b8f3e74
status: experimental
description: >
  Detects references to the NodeJS internal child_process module in
  application error logs, which appear when user-controlled input causes
  a child process spawning operation to fail. NodeJS exposes child_process
  as its built-in interface for executing OS-level commands from application
  code via functions such as exec, spawn, execFile, and fork. When an
  attacker injects malicious OS command syntax into a user-supplied parameter
  that is passed unsanitised to one of these functions, the resulting
  malformed command frequently causes the child process to fail and the
  NodeJS runtime to emit an error referencing the child_process module.
  The presence of child_process in an ERROR-level log entry is therefore
  a high-signal indicator that application code attempted to spawn an
  external process with attacker-influenced input, which is the defining
  characteristic of a server-side command injection attempt. This does
  not fire on successful execution, making it specifically useful for
  detecting probing and failed exploitation attempts during the attacker
  reconnaissance phase. Requires NodeJS application error logging to be
  configured at LOG_LEVEL ERROR or above and the resulting log stream
  to be forwarded to the SIEM; applications that suppress error output
  or redirect it to a sink not ingested by the pipeline will not surface
  these events.
references:
  - https://www.wix.engineering/post/threat-and-vulnerability-hunting-with-application-server-error-logs
author: Senior Threat Detection Engineer
date: 2026-05-25
tags:
  - attack.initial_access
  - attack.execution
  - attack.t1190
  - attack.t1059
logsource:
  product: nodejs
  category: application
  definition: >
    Requirements: application error logging must be enabled at LOG_LEVEL
    ERROR or above and the log stream must be ingested by the SIEM.
    NodeJS applications that suppress error output or run without a
    centralised logging configuration will not surface the events this
    rule depends on.
detection:
  keywords:
    - 'child_process'
  condition: keywords
falsepositives:
  - Legitimate application code that invokes child_process functions
    for approved purposes such as image processing, PDF generation, or
    shell script execution, where a transient system error unrelated to
    injection causes the spawning operation to fail and produce an
    ERROR-level log entry referencing the module.
  - Integration test suites that deliberately exercise error-handling
    paths in child process invocation code and emit ERROR-level log
    entries as part of expected test behaviour in non-production
    environments.
level: medium

# Arquivo: E.yml
title: NodeJS Child Process Execution Errors Indicative of Command Injection Attempts
id: a1b2c3d4-5e6f-47a8-9b0c-1d2e3f4a5b6c
status: experimental
description: Detects NodeJS application error logs where internal child_process module errors occur (e.g., spawn/exec failures). User-controlled input that triggers child process spawning errors is a strong indicator of attempted command injection or RCE exploitation. Requires application error logging at LOG_LEVEL ERROR or above and collection of full log messages.
author: Senior Threat Detection Engineer
date: 2026/06/10
references:
  - [https://www.wix.engineering/post/threat-and-vulnerability-hunting-with-application-server-error-logs](https://www.wix.engineering/post/threat-and-vulnerability-hunting-with-application-server-error-logs)
  - `https://nodejs.org/api/child_process.html` [(nodejs.org in Bing)](https://www.bing.com/search?q="https%3A%2F%2Fnodejs.org%2Fapi%2Fchild_process.html")
tags:
  - attack.execution
  - attack.initial_access
  - web
  - nodejs
logsource:
  product: nodejs
  category: application
  description: NodeJS application logs at LOG_LEVEL ERROR or above must be collected. Logs should include timestamp, LogLevel, and the full Message/StackTrace fields so internal module references and error strings are visible.
detection:
  selection_level:
    LogLevel|in:
      - 'ERROR'
      - 'Error'
      - 'error'
      - 'ERR'
  selection_message:
    Message|contains:
      - 'internal/child_process'
      - 'child_process.js'
      - 'child_process.exec'
      - 'child_process.spawn'
      - 'child_process.execFile'
      - 'spawn ENOENT'
      - 'spawn EACCES'
      - 'spawn EPERM'
      - 'Error: spawn'
      - 'Error: Command failed'
      - 'execvp'
      - 'command not found'
      - 'spawnSync'
      - 'fork()'
      - 'child process'
  condition: selection_level and selection_message
falsepositives:
  - Legitimate application errors due to missing external binaries, misconfiguration, or transient environment issues.
  - Development or CI jobs that intentionally invoke child processes and log failures during builds or tests.
level: high
