Generate a SIGMA rule to detect network connections initiated by MSBuild —
a signed Microsoft binary abused by SilentTrinity and similar C2 frameworks
to execute payloads while bypassing application allow-lists. Outbound traffic
from MSBuild to standard web ports is highly suspicious.

Target product: windows; log source category: network_connection.

Detection combines: (a) connecting process is msbuild.exe (|endswith);
(b) connection is outbound (Initiated true) to standard HTTP/HTTPS ports.
Use condition: `selection and filter`.

References to include:
- https://www.blackhillsinfosec.com/my-first-joyride-with-silenttrinity/


Nota
Aqui aparece um padrão de nomenclatura interessante: o bloco se chama filter mas a condição é selection and filter (AND positivo), não selection and not filter (exclusão). Ou seja, apesar do nome, ele funciona como uma segunda seleção. Mantive essa nomenclatura no prompt porque é exatamente o que aparece na regra original — algumas regras Sigma usam "filter" semanticamente errado, e parte do experimento é ver se as LLMs reproduzem essa convenção problemática ou se "corrigem" para nomes mais coerentes (como selection_port).
