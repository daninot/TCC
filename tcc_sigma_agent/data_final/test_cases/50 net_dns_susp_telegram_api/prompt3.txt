Generate a SIGMA rule to detect DNS queries to the Telegram Bot API endpoint —
malware families (TeleRAT, TeleCrypt, KillDisk) abuse Telegram bots as a
covert C2 channel that blends with legitimate messaging traffic.

Log source category: dns.

Detection matches DNS queries for the Telegram Bot API hostname using
exact-match (no modifier) on the query field.

References to include:
- https://core.telegram.org/bots/faq
- https://researchcenter.paloaltonetworks.com/2018/03/unit42-telerat-another-android-trojan-leveraging-telegrams-bot-api-to-target-iranian-users/
- https://blog.malwarebytes.com/threat-analysis/2016/11/telecrypt-the-ransomware-abusing-telegram-api-defeated/
- https://www.welivesecurity.com/2016/12/13/rise-telebots-analyzing-disruptive-killdisk-attacks/




Nota
Uma decisão sutil: a regra original usa match exato (query: 'api.telegram.org') em vez de |contains. Mencionei explicitamente "exact-match (no modifier)" porque o instinto natural de uma LLM ao ver "DNS query for a hostname" é usar |contains (para pegar subdomínios). Aqui o autor optou pela rigidez do match exato — provavelmente porque api.telegram.org é o único endpoint da Bot API, então |contains adicionaria FPs sem benefício. Reproduzir essa escolha estilística importa para a comparação.
